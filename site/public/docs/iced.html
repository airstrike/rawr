//rawr-iced

rawr-iced

rawr-iced runs iced apps written in Rawr. The app is a native iced app. Saving a .rawr file reloads it while the window stays open.

When rawr-iced is used

The rawr command reads a program once and decides who runs it. A program goes to rawr-iced when it names the iced crate. It also goes there when its rawr.toml has a [rust] table. Every other program runs on the base language. Set RAWR_VERBOSE=1 to see which way a program went.

rawr-iced follows iced master. It is built against one iced revision. rawr doctor prints that revision. Install rawr-iced as described in Getting started.

App shapes

An app starts from main with one of iced’s own entry points.

iced::run

iced::run(State::update, State::view) boots State::default(). The state type needs #[derive(Default)]. The counter on Getting started has this shape.

The application builder

iced::application(boot, update, view) takes a boot function such as State::default. It accepts these builders before .run():

  • .title(..) with a method of the state or a string literal.
  • .theme(..) with a method that returns a Theme.
  • .subscription(..) with a method that returns a Subscription.
  • .centered().

Window and renderer settings such as .window_size(..), .font(..) and .style(..) are accepted. rawr-iced doesn’t apply them yet.

update can return nothing or a Task<Message>. This app uses the builder, a Task, a text input and a list built at run time:

src/main.rawr
use iced::widget::{Column, Widget, button, column, row, text, text_input};
use iced::{Element, Fill, Task};

pub fn main() -> iced::Result {
    iced::application(Todos::default, Todos::update, Todos::view)
        .title("Todos")
        .run()
}

#[derive(Default)]
struct Todos {
    draft: String,
    items: Vec<String>,
}

#[derive(Debug, Clone)]
enum Message {
    Edit(String),
    Add,
    Remove(usize),
}

impl Todos {
    fn sample() -> Todos {
        Todos {
            draft: String::new(),
            items: vec!["Write the docs".to_string(), "Ship them".to_string()],
        }
    }

    fn update(&mut self, message: Message) -> Task<Message> {
        match message {
            Message::Edit(draft) => self.draft = draft,
            Message::Add => {
                if !self.draft.is_empty() {
                    self.items.push(self.draft.clone());
                    self.draft.clear();
                }
            }
            Message::Remove(index) => {
                self.items.remove(index);
            }
        }
        Task::none()
    }

    #[preview(name = "two items", seed = Todos::sample, size = (360, 180))]
    fn view(&self) -> impl Widget<Message> {
        let items: Vec<Element<'_, Message>> = self
            .items
            .iter()
            .enumerate()
            .map(|(index, item)| {
                row![text(item).width(Fill), button("x").on_press(Message::Remove(index))]
                    .spacing(8)
                    .boxed()
            })
            .collect();
        column![
            text_input("What needs doing?", &self.draft)
                .on_input(Message::Edit)
                .on_submit(Message::Add),
            Column::with_children(items).spacing(4),
        ]
        .spacing(12)
        .padding(16)
    }
}

Views and elements

A view returns impl Widget<Message> as views do in iced master. It can also return Element<'_, Message>.

To turn a widget into an Element, call .boxed(). The list above uses it to collect its rows into a Vec<Element>. .into() into an Element is not supported yet. The error says to use .boxed() instead.

Helper functions that build part of a view work when they name the app’s own Message type. A helper that is generic over the message type, such as fn padded<Message>(..), is not supported yet.

Components

A type can implement iced’s component::Component trait. Its state lives in the widget tree. Its events reach its own update. component(value) puts it in a view.

Subscriptions

A .subscription(..) method returns a Subscription<Message>. iced::time::every, iced::keyboard::listen, iced::event::listen and iced::window::frames work. Subscriptions combine with map and filter_map.

use iced::Subscription;
use iced::time::{self, Duration};

fn subscription(&self) -> Subscription<Message> {
    if self.running {
        time::every(Duration::from_millis(100)).map(|_| Message::Tick)
    } else {
        Subscription::none()
    }
}

Hot reload

rawr run opens the app and watches the project. Saving a .rawr file reloads the app in about 0.2 s. The window stays open and the app keeps its state.

A save that doesn’t pass the check doesn’t replace the running app. A bar in the window says Last good still running and shows the error. Its buttons retry, copy the error or reset the app.

Changing a Rust crate the app imports rebuilds that crate natively. The app reloads when the build finishes.

Press Cmd+Shift+S in the window to save a PNG of it.

Previews and snapshots

#[preview] marks a view function to render on its own. A view can have several. rawr check --as-rust leaves the attribute out, so a file with previews still compiles as Rust.

OptionMeaning
name = ".."The preview’s name.
group = ".."Groups previews. rawr preview steps through a group with the arrow keys.
seed = pathA function that builds the state to render, such as Todos::sample. Without it the state is Default.
update = pathThe update function to use in the preview window.
theme = pathA function that returns the Theme to render with.
themes = [..]Several theme functions. Each one gets its own snapshot.
size = (w, h)The canvas size in logical pixels.
snapshot = falseLeaves the preview out of rawr snapshot.
bind = (..)Arguments for a free view function that takes parameters.

rawr preview opens one preview in a window. It takes the preview’s name or group/name. Without a name it opens the last one you picked. The preview window reloads on save as rawr run does.

rawr snapshot --update renders every preview to a PNG under snapshots/. Commit those files. rawr snapshot --check renders them again and compares pixels. It exits with status 1 and names the first changed pixel when an image differs. The new images go under target/rawr/snapshots/ so you can compare them.

rawr snapshot --checkexit 1
Snapshot check found 1 mismatch(es) across 1 artifact(s):

[pixel drift] main::Clock::view#busy (native)
  expected: snapshots/Clock-6c008925/view/busy/native.png
  actual:   target/rawr/snapshots/Clock-6c008925/view/busy/native.png
  first changed pixel (38, 31): baseline [255, 255, 255, 255], actual [137, 137, 137, 255]

Importing your own Rust crates

An app can use items from your own Rust crates without bindings. List each crate under [rust.dependencies] in rawr.toml at the project root. List iced there too. Use the revision that rawr doctor prints. Importing your own Rust crates currently works only on Apple Silicon Macs.

rawr.toml
[rust.dependencies]
mathx = { path = "rust/mathx" }
iced = { git = "https://github.com/iced-rs/iced", rev = "be88873d38544455e26c7a104eb757da2cbbac6b" }
rust/mathx/src/lib.rs
pub fn double(x: i64) -> i64 {
    x * 2
}
src/main.rawr
use iced::widget::{Widget, button, column, text};
use mathx::double;

pub fn main() -> iced::Result {
    iced::run(App::update, App::view)
}

#[derive(Default)]
struct App {
    value: i64,
}

#[derive(Debug, Clone, Copy)]
enum Message {
    Bump,
}

impl App {
    fn update(&mut self, message: Message) {
        match message {
            Message::Bump => self.value += 1,
        }
    }

    fn view(&self) -> impl Widget<Message> {
        column![
            text(double(self.value)),
            button("Bump").on_press(Message::Bump),
        ]
    }
}

A dependency is an inline table. It takes the keys Cargo uses: path, git, rev, version, package, features and default-features. Use package when the crate’s name differs from the name you import, as in gallery_ui = { package = "gallery-ui", path = "rust/gallery-ui" }. The [rust] table can also set cargo-authority to a Cargo.toml. Rawr then uses that workspace and its lock file.

Rawr reads only the items your code uses. A custom iced widget written in Rust is imported like any other item. The crates compile with the pinned nightly on the first run, so that run takes longer.

A Rust type imported this way doesn’t provide derives to Rawr types yet. A Rawr struct with a field of an imported type can’t #[derive(Default)].

A rawr.toml can also list Rawr packages under [dependencies] with a path. The package’s own rawr.toml gives its name under [package].

Diagnostics

rawr check checks an app without opening a window. Errors look like rustc’s. Delete the Decrement arm from the counter and it reports the missing arm:

rawr checkexit 1
error[RAWR-RESOLVE-MATCH]: invalid match for `Message`: non-exhaustive patterns; missing Message::Decrement
 --> src/main.rawr:20:9-22:9
 20 |         match message {
    |         ^^^^^^^^^^^^^^^
    | ...
 22 |         }
    | ^^^^^^^^

The error code names the stage that failed and the kind of error. Codes will change while Rawr is pre-alpha.

What of iced is available

Most of iced’s everyday widgets and modules work. A missing one fails the check with unknown import.

Available

  • Layout: column!, row!, Column, Row, container, center, stack, space, scrollable, responsive, pin and lazy.
  • Controls: button, checkbox, toggler, radio, slider, vertical_slider, pick_list, combo_box, text_input and progress_bar.
  • Display: text, image, svg, qr_code, rule and tooltip.
  • Interaction: mouse_area, opaque, hover, sensor, component and widget::operation.
  • Modules: iced::time, iced::keyboard, iced::event, iced::window, iced::mouse, iced::font, iced::border and iced::theme. Color, color!, Length, Fill, Center and the other alignment names work.

An available widget may still miss some of its methods. For example, Checkbox::icon and Svg::style are not there yet.

Not available yet

  • canvas and iced::advanced. Without them you can’t write a custom widget in Rawr. Write it in Rust and import it instead.
  • pane_grid, rich_text, text_editor, markdown, table, grid, float, keyed_column and selector.
  • iced::gradient, Radians, Degrees, iced::clipboard, iced::task streams and the Function trait.
  • Multi-window apps (iced::daemon), shaders and wgpu.
  • async fn and .await.

iced’s own examples

iced master has 56 examples. Seven of them pass rawr check unchanged with their files renamed from .rs to .rawr: combo_box, counter, exit, pick_list, progress_bar, slider and tooltip. The biggest gap is canvas, which 13 examples use. About 20 examples need crates outside iced such as reqwest, tokio or rand. Some need native features such as file dialogs. The playground’s Examples menu has several of the passing examples ready to run.
