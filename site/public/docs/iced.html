//rawr-iced

rawr-iced

rawr-iced runs iced apps written in Rawr. The app is a native iced app. Saving a file marked // rawr reloads it while the window stays open.

When rawr-iced is used

The rawr command reads a program once and decides who runs it. A program goes to rawr-iced when it names the iced crate. It also goes there when it imports Rust crates from its Cargo.toml. Every other program runs on the base language. Set RAWR_VERBOSE=1 to see which way a program went.

rawr-iced follows iced master. It is built against one iced revision. rawr doctor prints that revision. Install rawr-iced as described in Getting started.

App shapes

An app starts from main with one of iced’s own entry points.

iced::run

iced::run(State::update, State::view) boots State::default(). The state type needs #[derive(Default)]. The counter on Getting started has this shape.

update and view can also be closures with typed parameters. iced::run(|state: &mut State, message: Message| state.update(message), State::view) is one example. A parameter can be a pattern such as _: Message. An update closure returns () unless it is written with a return type such as -> Task<Message>. An untyped closure parameter fails the check with an error that asks for its type.

The state can be any type with a Default. iced::run(|n: &mut u32, _: Message| *n += 1, |n: &u32| text(n)) keeps a u32.

The application builder

iced::application(boot, update, view) takes a boot function such as State::default. It accepts these builders before .run():

  • .title(..) with a method of the state or a string literal.
  • .theme(..) with a method that returns a Theme, or with a theme such as Theme::Dark.
  • .subscription(..) with a method that returns a Subscription.
  • .centered().

Window and renderer settings such as .window_size(..), .font(..) and .style(..) are accepted. rawr-iced doesn’t apply them yet.

update can return nothing or a Task<Message>. This app uses the builder, a Task, a text input and a list built at run time:

src/main.rs
// rawr
use iced::widget::{Column, Widget, button, column, row, text, text_input};
use iced::{Element, Fill, Task};
use rawr::preview;

pub fn main() -> iced::Result {
    iced::application(Todos::default, Todos::update, Todos::view)
        .title("Todos")
        .run()
}

#[derive(Default)]
struct Todos {
    draft: String,
    items: Vec<String>,
}

#[derive(Debug, Clone)]
enum Message {
    Edit(String),
    Add,
    Remove(usize),
}

impl Todos {
    fn sample() -> Todos {
        Todos {
            draft: String::new(),
            items: vec!["Write the docs".to_string(), "Ship them".to_string()],
        }
    }

    fn update(&mut self, message: Message) -> Task<Message> {
        match message {
            Message::Edit(draft) => self.draft = draft,
            Message::Add => {
                if !self.draft.is_empty() {
                    self.items.push(self.draft.clone());
                    self.draft.clear();
                }
            }
            Message::Remove(index) => {
                self.items.remove(index);
            }
        }
        Task::none()
    }

    #[preview(name = "two items", seed = Todos::sample, size = (360, 180))]
    fn view(&self) -> impl Widget<Message> {
        let items: Vec<Element<'_, Message>> = self
            .items
            .iter()
            .enumerate()
            .map(|(index, item)| {
                row![text(item).width(Fill), button("x").on_press(Message::Remove(index))]
                    .spacing(8)
                    .boxed()
            })
            .collect();
        column![
            text_input("What needs doing?", &self.draft)
                .on_input(Message::Edit)
                .on_submit(Message::Add),
            Column::with_children(items).spacing(4),
        ]
        .spacing(12)
        .padding(16)
    }
}

The line use rawr::preview; is there for cargo. The rawr-macros dependency provides it, as Previews and snapshots describes.

Views and elements

A view returns impl Widget<Message> as views do in iced master. It can also return Element<'_, Message>.

To turn a widget into an Element, call .boxed(). The list above uses it to collect its rows into a Vec<Element>. A widget’s .into() into an Element fails the check, as rustc rejects it on iced master. Element::from(widget) fails the same way. Both errors say to call .boxed() instead.

Row<Element<'_, Message>> and Column<Element<'_, Message>> name a row’s or a column’s type as iced master writes it. That works in a signature and in a let inside a function body.

Helper functions can build part of a view. A helper can name the app’s own Message type. It can also be generic over the message type, as in fn card<Message: Clone + 'static>(label: &str) -> Element<'static, Message>. Each caller passes its own message type. That type must be a type your program declares, a number, a String, a bool, a char or ().

Components

A type can implement iced’s component::Component trait. Its state lives in the widget tree. Its events reach its own update. component(value) puts it in a view.

Custom drawing with canvas

A type that implements canvas::Program<Message> draws in a canvas. Its draw returns the geometry to show. update and mouse_interaction are optional, as in iced. update turns iced’s events into a canvas::Action, which can publish a message, request a redraw or capture the event. The program’s State lives in the widget tree.

  • canvas(program) and Canvas::new(program) make the widget. canvas(self) works in a view.
  • Frame has fill, stroke, fill_rectangle, stroke_rectangle, fill_text, translate, rotate, scale, with_save, center and into_geometry.
  • Path has circle, line, rectangle and rounded_rectangle. Path::new(|b| ..) builds one with move_to, line_to, arc_to, circle, rectangle, quadratic_curve_to, bezier_curve_to and close.
  • Stroke, Fill and canvas::Text take struct literals with ..Default::default(). Stroke also has with_width, with_color, with_line_cap and with_line_join.
  • Cache keeps what its draw drew until clear is called or the size changes.
  • The same names import from iced::advanced::graphics::geometry.

Gradients, images, with_clip, Degrees and Radians are not there yet. rotate takes radians as a float.

sun.rs
use iced::mouse;
use iced::widget::canvas::{Cache, Geometry, LineCap, Path, Stroke};
use iced::widget::{canvas, center};
use iced::{Color, Element, Point, Rectangle, Renderer, Theme, Vector};

#[derive(Default)]
struct Sun {
    rays: Cache,
}

#[derive(Debug, Clone)]
enum Message {}

impl Sun {
    fn update(&mut self, _message: Message) {}

    fn view(&self) -> Element<'_, Message> {
        center(canvas(self).width(240).height(240)).boxed()
    }
}

impl<Message> canvas::Program<Message> for Sun {
    type State = ();

    fn draw(
        &self,
        _state: &(),
        renderer: &Renderer,
        _theme: &Theme,
        bounds: Rectangle,
        _cursor: mouse::Cursor,
    ) -> Vec<Geometry> {
        let sun = self.rays.draw(renderer, bounds.size(), |frame| {
            let center = frame.center();
            frame.fill(&Path::circle(center, 50.0), Color::from_rgb8(0xff, 0xb3, 0x00));
            frame.translate(Vector::new(center.x, center.y));
            for ray in 0..12 {
                frame.with_save(|frame| {
                    frame.rotate(ray as f32 * std::f32::consts::PI / 6.0);
                    frame.stroke(
                        &Path::line(Point::new(70.0, 0.0), Point::new(100.0, 0.0)),
                        Stroke::default()
                            .with_width(6.0)
                            .with_color(Color::from_rgb8(0xff, 0x2e, 0x93))
                            .with_line_cap(LineCap::Round),
                    );
                });
            }
        });
        vec![sun]
    }
}

fn main() -> iced::Result {
    iced::run(Sun::update, Sun::view)
}

Widgets of your own

A type can implement iced’s advanced::Widget trait, as iced’s custom_widget, custom_quad, geometry and loupe examples do. A value of that type goes in a view like any other widget. The trait is iced master’s, so layout sets tree.size and returns nothing.

  • size, layout and draw are required. update, mouse_interaction, tag, state, diff, operate and overlay are optional. A method the impl leaves out runs iced’s own default, without calling your code.
  • draw fills quads with renderer.fill_quad. It draws meshes with draw_mesh. renderer::Quad takes its bounds, border, shadow and snap. with_translation and with_transformation run their closure where they are written, as in iced.
  • update receives iced’s events. Its Shell publishes a message, requests a redraw or captures the event.
  • A widget can wrap an Element, as loupe does. It forwards size, layout, draw, update, operate, overlay and the rest to it. iced shows the first overlay its overlay returns. The wrapped widget draws in its place among the widget’s own drawing, inside the transformation and clipping around it.
  • A widget keeps a State of its own with tree::Tag::of::<State>() and tree::State::new(value). tree.state.downcast_ref::<State>() reads it. let state = tree.state.downcast_mut::<State>(); changes it. A reload keeps the State while its type and its fields stay the same. A change to them starts it again from state.
  • Size<Length>, layout::Limits, Layout, Transformation, Rectangle::expand, graphics::color::pack and iced::Never work as in iced. iced::run((), view) runs a view whose Message is Never.

A widget’s drawing is kept while its draw runs and shown when draw returns. A call that fails shows its error in the widget’s bounds. Its drawing and its Shell requests are dropped.

A panic in a wrapped Element’s own code is an error of the call that reached it. ?play and snapshots draw with tiny-skia, which does not draw meshes. A mesh shows in a window.

circle.rs
use iced::advanced::layout::{self, Layout};
use iced::advanced::renderer;
use iced::advanced::widget::{self, Widget};
use iced::widget::{center, column, slider, text};
use iced::{border, mouse, Center, Color, Length, Rectangle, Size};

struct Circle {
    radius: f32,
}

impl widget::Meta for Circle {}

impl<Message, Theme, Renderer> Widget<Message, Theme, Renderer> for Circle
where
    Renderer: renderer::Renderer,
{
    fn size(&self) -> Size<Length> {
        Size {
            width: Length::Shrink,
            height: Length::Shrink,
        }
    }

    fn layout(&mut self, tree: &mut widget::Tree, _renderer: &Renderer, _limits: &layout::Limits) {
        tree.size = Size::new(self.radius * 2.0, self.radius * 2.0);
    }

    fn draw(
        &self,
        _tree: &widget::Tree,
        renderer: &mut Renderer,
        _theme: &Theme,
        _style: &renderer::Style,
        layout: Layout,
        _cursor: mouse::Cursor,
        _viewport: &Rectangle,
    ) {
        renderer.fill_quad(
            renderer::Quad {
                bounds: layout.bounds(),
                border: border::rounded(self.radius),
                ..renderer::Quad::default()
            },
            Color::from_rgb8(0xff, 0x2e, 0x93),
        );
    }
}

struct App {
    radius: f32,
}

impl Default for App {
    fn default() -> Self {
        App { radius: 50.0 }
    }
}

#[derive(Debug, Clone, Copy)]
enum Message {
    Radius(f32),
}

impl App {
    fn update(&mut self, message: Message) {
        match message {
            Message::Radius(radius) => self.radius = radius,
        }
    }

    fn view(&self) -> impl iced::Widget<Message> {
        let radius = self.radius;
        center(
            column![
                Circle { radius },
                text!("Radius: {radius:.0}"),
                slider(10.0..=100.0, radius, Message::Radius),
            ]
            .spacing(20)
            .width(300)
            .align_x(Center),
        )
    }
}

fn main() -> iced::Result {
    iced::run(App::update, App::view)
}
rawr run circle.rs(opens a window)

Subscriptions

A .subscription(..) method returns a Subscription<Message>. iced::time::every, iced::keyboard::listen, iced::event::listen and iced::window::frames work. Subscriptions combine with map and filter_map. Subscription::run(builder) takes a Rust function that returns a sipper, as Async code describes.

use iced::Subscription;
use iced::time::{self, Duration};

fn subscription(&self) -> Subscription<Message> {
    if self.running {
        time::every(Duration::from_millis(100)).map(|_| Message::Tick)
    } else {
        Subscription::none()
    }
}

Hot reload

rawr run opens the app and watches the crate. Saving a file marked // rawr reloads the app in about 0.2 s. The window stays open and the app keeps its state.

A save that doesn’t pass the check doesn’t replace the running app. A bar in the window says Last good still running and shows the error. Its buttons retry, copy the error or reset the app.

Saving a native module or the source of a dependency rebuilds it natively. The app reloads when the build finishes.

rawr run also runs cargo check in the background when the app opens and after each save. Its errors appear in a card at the top of the window and on stderr. They don’t block the reload.

Press Cmd+Shift+S in the window to save a PNG of it.

Previews and snapshots

#[preview] marks a view function to render on its own. A view can have several. The attribute comes from the rawr-macros crate, whose library name is rawr. Add it to [dependencies] in Cargo.toml:

Cargo.toml
rawr-macros = { git = "https://github.com/airstrike/rawr" }

Then write #[rawr::preview(..)], or write use rawr::preview; and then #[preview(..)]. Under cargo the attribute leaves the item as written. Rawr reads it itself. Cargo doesn’t warn about a function that only previews use. The crate is not on crates.io yet.

OptionMeaning
name = ".."The preview’s name.
group = ".."Groups previews. rawr preview steps through a group with the arrow keys.
seed = pathA function that builds the state to render, such as Todos::sample. Without it the state is Default.
update = pathThe update function to use in the preview window.
theme = pathA function that returns the Theme to render with.
themes = [..]Several theme functions. Each one gets its own snapshot.
size = (w, h)The canvas size in logical pixels.
snapshot = falseLeaves the preview out of rawr snapshot.
bind = (..)Arguments for a free view function that takes parameters.

rawr preview opens one preview in a window. It takes the preview’s name or group/name. Without a name it opens the last one you picked. The preview window reloads on save as rawr run does.

rawr snapshot --update renders every preview to a PNG under snapshots/. Commit those files. rawr snapshot --check renders them again and compares pixels. It exits with status 1 and names the first changed pixel when an image differs. The new images go under target/rawr/snapshots/ so you can compare them.

rawr snapshot --checkexit 1

[pixel drift] clock::Clock::view#busy (native)

Importing your own Rust crates

An app can use items from your own Rust crates without bindings. List each crate under [dependencies] in the crate’s Cargo.toml. List iced there too. Use the revision that rawr doctor prints. Importing your own Rust crates needs a Unix system. It has only been tested on Apple Silicon Macs so far.

Cargo.toml
[dependencies]
mathx = { path = "mathx" }
iced = { git = "https://github.com/iced-rs/iced", rev = "be88873d38544455e26c7a104eb757da2cbbac6b" }
mathx/src/lib.rs
pub fn double(x: i64) -> i64 {
    x * 2
}
src/main.rs
// rawr
use iced::widget::{Widget, button, column, text};
use mathx::double;

pub fn main() -> iced::Result {
    iced::run(App::update, App::view)
}

#[derive(Default)]
struct App {
    value: i64,
}

#[derive(Debug, Clone, Copy)]
enum Message {
    Bump,
}

impl App {
    fn update(&mut self, message: Message) {
        match message {
            Message::Bump => self.value += 1,
        }
    }

    fn view(&self) -> impl Widget<Message> {
        column![
            text(double(self.value)),
            button("Bump").on_press(Message::Bump),
        ]
    }
}

Rawr uses the dependencies as cargo resolves them. Workspace inheritance works. A path dependency is built natively, even if its files start with // rawr. Only the crate you run is interpreted.

A module of your crate whose first line is not // rawr is native Rust too. rawr run builds it with cargo and rebuilds it when you save it. Native code must not use code from marked files. Rawr reports an error if it does.

Rawr reads only the items your code uses. A custom iced widget written in Rust is imported like any other item. The crates compile with the pinned nightly on the first run, so that run takes longer.

A Rawr struct can hold a value of an imported type. It can #[derive(Default)] when the crate implements Default for that type. The field then takes the crate’s default(), as in Rust. It can also derive Debug, Clone and Copy when the crate implements them for that type. {:?} of an imported value prints the crate’s Debug text. to_string() and {} of an imported value print its Display text. A Message can hold an imported value, and a match can bind it.

A Rust method that takes a &str takes a Rawr string. A method whose result Rawr cannot hold returns that result’s Display text instead, when its type has one. So chrono’s now.format("%H:%M:%S") is a String.

A field of an imported type that is Copy reads as a copy, as in Rust. .clone() of an imported value leaves the original usable, as in Rust.

A match or if let can match a variant of an imported enum, as in echo::Event::Connected(connection) => ... The pattern takes the variant’s fields as clones. A path through a native module, such as download::Progress in a field, names the type even beside a function called download.

An edit to your Rawr code applies to a running app whose State holds a value of an imported type. The value keeps its state across the edit. An edit to the dependency’s Rust code starts a new app, and its State starts again from its default. The window then names the imported type that did not carry over.

Async code

An app runs futures as iced tasks. A Rust function that returns a future gives a Task. That covers an async fn in a Rust crate and tokio::time::sleep. A Rust method that takes self by value and returns a future gives one too, as reqwest’s Response::text does. A Rust function that returns an iced Task, such as system::information(), gives that task.

// rawr
mod fetch; // native Rust: pub async fn size(url: String) -> usize

fn update(&mut self, message: Message) -> Task<Message> {
    match message {
        Message::Load => Task::perform(fetch::size(self.url.clone()), Message::Loaded),
        Message::Loaded(size) => {
            self.size = Some(size);
            Task::none()
        }
    }
}

Task::perform, Task::future, Task::sip, Task::abortable with task::Handle and Subscription::run work. Task::sip and Subscription::run take a Rust sipper. The Rawr code that maps a task’s values runs on the UI thread.

A variant passed as a function keeps its payload’s type. So .map(Message::Number) maps a Task<u32> when Number holds a u32. Task::<Message>::none() names the task’s message type with a turbofish, as in Rust.

A task’s future runs on iced’s thread pool, so it must be Send, as iced requires. rawr check names the Rust function whose future is not.

A reload cancels the tasks the app is running. Their handles report is_aborted(), and the status line says that a running task was cancelled. The State keeps what it held, so a download the reload cancelled still shows as running until a message changes it.

Async Rawr code

Rawr code can be async too. async fn, async blocks, async move blocks and async closures work. .await takes a future’s output inside them. An async fn returns impl Future<Output = T> of its declared output, as in Rust. Rawr runs such a future as iced’s Task<T>, so Task::perform takes it.

use iced::task::sipper;
use std::time::Duration;

fn start() -> (Download, Task<Message>) {
    let download = sipper(async |mut progress| {
        for step in 0..=10 {
            progress.send(step as f32 * 10.0).await;
            tokio::time::sleep(Duration::from_millis(100)).await;
        }
    });
    (Download::default(), Task::sip(download, Message::Progress, |_| Message::Done))
}

iced::task::sipper takes an async closure. The closure sends its progress with progress.send(value).await. Task::sip maps each value it sends, and then its output.

An async body runs on the UI thread, one step at a time. It stops at each .await and goes on from there once the future ends. Its locals keep their values in between, and no work it did runs again. .await works in a loop, a branch, a match arm and a call’s arguments. ? returns from the async body, as in Rust.

futures::future::join and try_join run two futures at once, through iced’s iced::futures. try_join ends at the first Err.

A program that does not depend on tokio still has tokio::time::sleep. Rawr runs its own, which waits on a thread. In ?play it follows the recording’s clock, so the GIF shows each step.

A reload that changes an async body cancels the task that runs it. A suspended body never goes on with the new code.

tokio::task::spawn_blocking with a Rawr closure does not work yet. A Rust async method that borrows its receiver does not cross either.

What of iced is available

Most of iced’s everyday widgets and modules work. A missing one fails the check with unknown import.

Available

  • Layout: column!, row!, Column, Row, container, center, stack, space, scrollable, responsive, pin and lazy.
  • Controls: button, checkbox, toggler, radio, slider, vertical_slider, pick_list, combo_box, text_input and progress_bar.
  • Display: text, image, svg, qr_code, rule and tooltip. Svg::style takes a style function. image::Handle has from_path, from_bytes and from_rgba. svg::Handle has from_path and from_memory.
  • Rich text: rich_text, rich_text! and span. A string works as a span. on_link_click maps a span’s link to a message. A span without a link needs no link type.
  • Drawing: canvas, as above, and widgets of your own, as above.
  • Interaction: mouse_area, opaque, hover, sensor, component and widget::operation.
  • float draws its content scaled and moved above the rest. It takes scale, translate with a function of the content’s bounds and the viewport, and style with a function of the theme that returns a float::Style.
  • selector::find with a widget Id. Its Target has bounds and visible_bounds.
  • Modules: iced::time, iced::keyboard, iced::event, iced::window, iced::mouse, iced::font, iced::border and iced::theme. font::list() lists the system’s font families. Seed::LIGHT and iced’s other built-in seeds are in iced::theme::palette. Color, color!, Length, Fill, Center and the other alignment names work, also by their full paths such as iced::Center. space::horizontal() and space::vertical() work. std::time names iced::time’s Duration and Instant.

An available widget may still miss some of its methods. Rotation::radians_mut works, so *rotation.radians_mut() = angle turns a rotation in place. Animation<T> animates a bool or a number with go, go_mut, is_animating and interpolate at an Instant. go also ends a chain of builders, as in Animation::new(false).quick().go(true, now). A Vector adds, subtracts, and scales by an f32. A Point moves by a Vector, and two points differ by one. color!(0xffc8a8, alpha) and color!(r, g, b, alpha) take any f32 alpha. A helper such as text passes as a function, as in .map(text). A canvas program’s State may be a RefCell. canvas::Group and Cache::with_group work. A function of yours that takes impl Into<Length> takes a number or a Length.

Statements before the app

main may run statements before iced::application or iced::run, such as tracing_subscriber::fmt::init();. They run once, when rawr run starts, as Rust runs main once. A reset or a reload boots the app again without them. An edit to them takes effect when rawr run restarts, and the window says so. #[cfg(..)] on a statement and cfg! follow the machine Rawr runs on.

Not available yet

  • A widget type of your own that borrows, as Circular<'a, Theme> does.
  • pane_grid, text_editor, markdown, grid and keyed_column.
  • iced::gradient, iced::clipboard and application::timed.
  • Multi-window apps (iced::daemon), shaders and wgpu.
  • tokio::task::spawn_blocking with a Rawr closure. Other async code works, as Async code describes.

iced’s own examples

iced master has 56 examples. 32 of them pass rawr check with // rawr added as the first line of their files: arc, bezier_tool, checkbox, combo_box, component, counter, custom_quad, custom_widget, delineate, download_progress, events, exit, geometry, lazy, loupe, modal, pick_list, progress_bar, qr_code, scrollable, slider, stopwatch, styling, svg, system_information, table, text, toast, tooltip, url_handler, vectorial_text and websocket. Six of the others use async code and now stop at other gaps. Two need iced::application::timed. The rest need iced items or Rust features listed above. The playground’s Examples menu has several of the passing examples ready to run.
