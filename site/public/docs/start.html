Get started

Install the rawr command and start a crate. Run it, make an error, then build it for release with Cargo.

Install

Install the rawr command. It needs Rust 1.95 or newer.

cargo install --locked --git https://github.com/airstrike/rawr rawr-cli

The rawr-cli package installs rawr. It also installs cargo-rawr, so cargo rawr run works too. Run rawr doctor to see what is installed.

A first crate

rawr new hello && cd hello && rawr run

rawr new hello creates the hello directory. It holds a Cargo crate with Cargo.toml and src/main.rs. The crate has no dependencies.

src/main.rs
// rawr
// `rawr run` interprets this file, and `cargo build` compiles it as
// ordinary Rust.

struct Greeting {
    name: String,
    times: i64,
}

impl Greeting {
    fn line(&self, count: i64) -> String {
        format!("{count}. Hello, {}!", self.name)
    }
}

fn main() {
    let greeting = Greeting {
        name: String::from("rawr"),
        times: 3,
    };
    for count in 1..=greeting.times {
        println!("{}", greeting.line(count));
    }
}
rawr run1. Hello, rawr! 2. Hello, rawr! 3. Hello, rawr!

The first line, // rawr, marks the file. rawr run checks it and then interprets it. cargo run compiles the same file and prints the same three lines.

rawr run runs the program once and exits. Edit src/main.rs and run it again. A crate with no dependencies needs no build, so the edit runs at once. Reload on save for a program like this one is planned. iced apps reload today, with rawr-iced.

Errors

rawr checks the whole program before any of it runs. Change greeting.line(count) to greeting.lines(count) and run it again:

rawr runexit 1
error[E0599]: no method named `lines` found for `Greeting` in the current scope
 --> /home/you/hello/src/main.rs:22:33-22:38
 22 |         println!("{}", greeting.lines(count));
    |                                 ^^^^^

The program doesn’t start, so nothing is printed before the error. Where rustc has an error for the same mistake, rawr uses rustc’s code and wording. rawr reports one error at a time.

For a crate, rawr run also runs cargo check beside the program. Its errors are printed after the program ends, so here rustc reports the same mistake a second time.

Check without running

rawr check runs rawr’s check and then cargo check. It prints Checked and the path, then cargo check passed. It exits with status 1 if either check fails.

rawr’s check is not rustc. It accepts some code that rustc rejects, so rustc has the final word. Supported Rust lists those cases.

A single file

rawr run also takes one .rs file. A single file doesn’t need the marker.

cart.rs
// rawr
enum Item {
    Book { price: f64 },
    Coffee { cups: i64 },
}

trait Priced {
    fn price(&self) -> f64;
}

impl Priced for Item {
    fn price(&self) -> f64 {
        match self {
            Item::Book { price } => *price,
            Item::Coffee { cups } => 3.5 * (*cups as f64),
        }
    }
}

fn total(items: &[Item]) -> f64 {
    let mut sum = 0.0;
    for item in items {
        sum += item.price();
    }
    sum
}

fn main() {
    let cart = vec![Item::Book { price: 20.0 }, Item::Coffee { cups: 2 }];
    println!("total: {}", total(&cart));
}
rawr run cart.rstotal: 27

A single file can hold items, top-level statements, or both. Top-level statements run first, as the body of fn main would, and then fn main runs. Cargo would not build a file of top-level statements, so keep those to snippets and the playground.

The run button sends the file to rawr’s server and shows what it printed there.

Native modules and dependencies

A module whose first line isn’t // rawr is native Rust. So is every crate in [dependencies]. A crate with either one goes to rawr-import, which compiles the native code with Cargo. The marked code calls it.

The crate root may stay native. Mark only the module you are working on, and your native main calls it through rawr. A save of that module reaches the running program at its next call. A native main says what crosses and when the program restarts.

Build for release

cargo build --release

Cargo compiles every file natively. The marker is a comment, so the release build has no interpreter in it.
