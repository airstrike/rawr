Start

Install rawr and run your first crate without compiling it. The same files build for release with Cargo.

Install

rawr needs Rust 1.95 or newer.

cargo install --locked --git https://github.com/airstrike/rawr rawr-cli

This also installs cargo-rawr, so cargo rawr run works too.

A first crate

rawr new hello && cd hello && rawr run

rawr new hello creates a Cargo crate with no dependencies.

src/main.rs
// rawr
// `rawr run` interprets this file, and `cargo build` compiles it as
// ordinary Rust.

struct Greeting {
    name: String,
    times: i64,
}

impl Greeting {
    fn line(&self, count: i64) -> String {
        format!("{count}. Hello, {}!", self.name)
    }
}

fn main() {
    let greeting = Greeting {
        name: String::from("rawr"),
        times: 3,
    };
    for count in 1..=greeting.times {
        println!("{}", greeting.line(count));
    }
}
rawr run1. Hello, rawr! 2. Hello, rawr! 3. Hello, rawr!

The // rawr line marks the file for rawr to interpret. cargo run compiles the same file and prints the same three lines.

A crate with no dependencies needs no build, so an edit runs at once.

In a terminal, rawr run keeps watching after the program ends. Each save runs it again, and Ctrl-C stops it. Arguments after -- go to the program, as Run describes.

Errors

rawr checks the whole program before any of it runs. Change greeting.line(count) to greeting.lines(count) and save:

rawr runexit 1
error[E0599]: no method named `lines` found for `Greeting` in the current scope
 --> /home/you/hello/src/main.rs:22:33-22:38
 22 |         println!("{}", greeting.lines(count));
    |                                 ^^^^^

Where rustc has an error for the same mistake, rawr uses rustc’s code and wording. rawr reports one error at a time.

For a crate, rawr run also runs cargo check. Its errors are printed after the program ends, so rustc reports this mistake a second time.

Check without running

rawr check runs rawr’s check and then cargo check. rawr’s check accepts some code that rustc rejects, so rustc has the final word. The Overview lists those cases.

A single file

rawr run also takes one .rs file. A single file doesn’t need the marker.

cart.rs
// rawr
enum Item {
    Book { price: f64 },
    Coffee { cups: i64 },
}

trait Priced {
    fn price(&self) -> f64;
}

impl Priced for Item {
    fn price(&self) -> f64 {
        match self {
            Item::Book { price } => *price,
            Item::Coffee { cups } => 3.5 * (*cups as f64),
        }
    }
}

fn total(items: &[Item]) -> f64 {
    let mut sum = 0.0;
    for item in items {
        sum += item.price();
    }
    sum
}

fn main() {
    let cart = vec![Item::Book { price: 20.0 }, Item::Coffee { cups: 2 }];
    println!("total: {}", total(&cart));
}
rawr run cart.rstotal: 27

A single file may also hold top-level statements. They run first, and then fn main runs. Cargo won’t build a file of top-level statements, so keep them to snippets and the playground.

Native modules and dependencies

A module whose first line isn’t // rawr is native Rust. So is every crate in [dependencies]. rawr-import compiles native code with Cargo, and marked code calls it. Imports sets it up.

The crate root may stay native. Mark only the module you are working on, and your native main calls into it. A save of that module reaches the running program at its next call. Run says what crosses and when the program restarts.

Build for release

cargo build --release

The marker is a comment, so the release build has no interpreter in it.
