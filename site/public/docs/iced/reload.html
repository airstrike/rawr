//rawr-iced

Reload an iced app

What happens when you save while an iced app runs under rawr run. What it keeps, what starts again and what rebuilds.

Saving a marked file

rawr run opens the app and watches the crate. Saving a file marked // rawr checks the new code and swaps it into the running app. The window stays open.

An edit to a marked file needs no native build. In RawrGallery, a gallery app built with rawr-iced, such an edit was live in about 0.2 s on an Apple Silicon Mac.

rawr run also runs cargo check in the background when the app opens and after each save. Its errors appear in a card at the top of the window and on stderr. They don’t block the reload.

What a reload keeps

The app keeps its state when the new code is compatible with it. A change to the state’s own types can make it incompatible. Then the app boots again: iced::run starts from Default, and iced::application runs its boot function.

An edit to a marked file applies to a running app whose State holds a value of an imported type. The value keeps its state across the edit. An edit to the dependency’s Rust code starts a new app, and its State starts again from its default. The window then names the imported type that did not carry over.

A save that fails the check

A save that doesn’t pass the check doesn’t replace the running app. A bar in the window says Last good still running and shows the error. Its buttons retry, copy the error or reset the app.

Native edits

Saving a native module or the source of a dependency rebuilds it with Cargo. The app reloads when the build finishes. In RawrGallery on a busy Apple Silicon Mac, the new window was up about 8 s after such a save.

Tasks and async code

A reload cancels the tasks the app is running. Their handles report is_aborted(), and the status line says that a running task was cancelled. The State keeps what it held, so a download the reload cancelled still shows as running until a message changes it.

A reload that changes an async body cancels the task that runs it. A suspended body never goes on with the new code.

A reload drops the output of a spawn_blocking closure that is still running. It can’t stop the thread, which ends when the closure returns.

Statements before the app

main may run statements before iced::application or iced::run, such as tracing_subscriber::fmt::init();. They run once, when rawr run starts, as Rust runs main once. A reset or a reload boots the app again without them. An edit to them takes effect when rawr run restarts, and the window says so. #[cfg(..)] on a statement and cfg! follow the machine rawr runs on.
