//The language

The language

Rawr is written in Rust syntax and checked before it runs. This page lists the Rust that works today, what doesn’t work yet and where a program behaves differently from the same code built by cargo.

How a program runs

Rawr checks a whole program before any of it runs. The check resolves names and types, traits and method calls. It also checks that every match covers every case. A program that fails the check doesn’t start.

A program is one file or a project directory. In a project, the entry file is src/main.rawr. A file can hold items, top-level statements, or both. Rawr runs the top-level statements first and then calls fn main if there is one.

This program uses ?, a Result from main and a closure. It prints the same output as the Rust binary and exits with the same status.

parse.rawr
fn parse(s: &str) -> Result<i64, String> {
    s.parse::<i64>().map_err(|e| format!("{s:?}: {e}"))
}

fn main() -> Result<(), String> {
    let n = parse("42")?;
    println!("n = {n}");
    let m = parse("forty")?;
    println!("m = {m}");
    Ok(())
}
rawr run parse.rawrn = 42 Error: "\"forty\": invalid digit found in string"

The exit status is 1. A panic exits with status 101. Rust uses the same statuses.

Items

  • fn. A function can be nested inside another function.
  • struct with named fields, tuple structs and unit structs.
  • enum with unit, tuple and struct variants.
  • impl blocks with methods, associated functions and associated consts.
  • trait with default methods, associated types and static functions. Traits can be implemented for your own types and for built-in types such as i64.
  • const and static items.
  • mod. A mod util; declaration loads util.rawr beside the file that declares it. An inline mod m { .. } works too.
  • use with paths and groups, such as use std::collections::{HashMap, HashSet};.
  • #[derive] of Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash and Default. Rawr checks a derive the way rustc does. Deriving Copy on a struct with a String field is an error.

Types

  • Integers: i8, i16, i32, i64, isize, u8, u16, u32, u64 and usize. Overflow panics as it does in a Rust debug build. The wrapping_*, checked_*, saturating_* and overflowing_* methods work.
  • Floats: f32 and f64. Methods such as sqrt, powi, floor, round and trunc work.
  • bool, char, String and &str.
  • Tuples and Vec.
  • Arrays such as [0; 3] and slices such as &v[1..3].
  • Option and Result with their usual methods and the ? operator.
  • Box<T> and Box<dyn Trait>.
  • impl Trait in argument and return position. This covers impl Fn(i64) -> i64 and impl Iterator<Item = i64>.
  • Function pointers such as fn(i64) -> i64.
  • as casts between numbers. They truncate and saturate as Rust’s do. u8 as char works too.

Mixing numeric types without a cast is an error in Rawr too. i32 + i64 doesn’t pass the check. Indexing a Vec takes a usize.

Generics and traits

Functions, structs, enums and impl blocks can be generic. Bounds work inline and in where clauses. A generic type without the bound it needs fails the check. rustc rejects it too.

generics.rawr
use std::fmt;
use std::ops::Add;

struct Stack<T> {
    items: Vec<T>,
}

impl<T: Clone> Stack<T> {
    fn new() -> Self {
        Stack { items: Vec::new() }
    }

    fn push(&mut self, item: T) {
        self.items.push(item);
    }

    fn top(&self) -> Option<T> {
        self.items.last().cloned()
    }
}

#[derive(Debug, Clone, Copy, PartialEq)]
struct Meters(f64);

impl Add for Meters {
    type Output = Meters;

    fn add(self, other: Meters) -> Meters {
        Meters(self.0 + other.0)
    }
}

impl fmt::Display for Meters {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "{} m", self.0)
    }
}

fn largest<T: PartialOrd + Copy>(items: &[T]) -> T {
    let mut max = items[0];
    for &item in items {
        if item > max {
            max = item;
        }
    }
    max
}

fn main() {
    let mut stack = Stack::new();
    stack.push(Meters(1.5) + Meters(2.0));
    println!("{}", stack.top().unwrap());
    println!("{}", largest(&[3, 9, 2]));
}
rawr run generics.rawr3.5 m 9

Trait objects work through Box<dyn Trait>. A Vec<Box<dyn Shape>> can hold different types that implement Shape. Implementing Iterator for your own type gives it map, filter, collect and the other adapters. Operator traits from std::ops such as Add work.

Patterns and control flow

  • match with literals, ranges such as 3..=9, alternatives with |, guards and name @ pattern bindings.
  • Struct, tuple and enum patterns. .. matches the rest.
  • Slice patterns such as [first, .., last].
  • if let, while let and let .. else.
  • loop, while and for. Loop labels work. break can carry a value.
  • Blocks are expressions. let x = { .. }; works.
  • Patterns on &mut places write their bindings back. for p in &mut points { p.x += 1; } changes the elements.

Closures

Closures capture their environment. move closures work. A closure that mutates what it captures is FnMut. Functions can take closures as impl Fn(..) or as a generic F: Fn(..). They can return them as impl Fn(..) or Box<dyn Fn(..)>. A struct field can hold a Box<dyn Fn(..)>.

closures.rawr
fn apply(f: impl Fn(i64) -> i64, x: i64) -> i64 {
    f(x)
}

fn scale(k: i64) -> impl Fn(i64) -> i64 {
    move |x| x * k
}

fn main() {
    let mut log = Vec::new();
    let mut add = |line: &str| log.push(line.to_string());
    add("first");
    add("second");
    println!("{:?}", log);
    println!("{} {}", apply(|x| x + 1, 1), scale(3)(2));
    let odd_squares: Vec<i64> = (1..=10).filter(|x| x % 2 == 1).map(|x| x * x).collect();
    println!("{:?}", odd_squares);
}
rawr run closures.rawr["first", "second"] 2 6 [1, 9, 25, 49, 81]

Macros

Rawr has a fixed set of built-in macros. You can’t define your own with macro_rules!.

MacroNotes
println! print!Write to stdout.
eprintln! eprint!Write to stderr.
format!Builds a String. Takes the same format strings as the print macros.
write!Writes to a Formatter inside a Display or Debug impl.
panic!Stops the program with exit status 101.
assert! assert_eq! assert_ne!Panic when the condition fails. They take an optional message.
debug_assert! debug_assert_eq!Behave as in a Rust debug build.
unreachable! todo! unimplemented!Panic when reached.
vec!Both forms: vec![1, 2] and vec![0; n].
matches!Takes a guard: matches!(x, Some(n) if n > 2).
concat! stringify!Expand to a string literal.
env!Reads an environment variable when the program is checked.
include_str! include_bytes!Read a file relative to the source file.

Format strings

Format strings follow Rust’s rules. All of these work:

  • Positional, numbered and named arguments.
  • Captured variables such as {name}.
  • Fill, alignment, width and precision: {:>8}, {:^7}, {:08.3}, {:.2}.
  • Width and precision from an argument: {:>w$}, {:>1$}, {:.*}.
  • Signs and radix: {:+}, {:#x}, {:X}, {:#b}, {:o}, {:e}.
  • {:?} and {:#?}. Strings and chars are escaped as Rust escapes them.

Hex debug output ({:x?}) is not supported yet.

The standard library

Rawr provides part of std. These work today:

  • String and &str: push, push_str, insert, pop, remove, truncate, clear, trim, find, replace, split, splitn, split_whitespace, lines, chars, char_indices, bytes, as_bytes, starts_with, contains, to_uppercase, parse, String::from_utf8 and more. len counts bytes as Rust’s does.
  • Vec and slices: push, pop, insert, remove, retain, extend, dedup, sort, sort_by, sort_by_key, contains, windows, chunks, first, last, Vec::with_capacity and more.
  • Iterators: map, filter, enumerate, zip, skip, take, step_by, rev, any, all, position, fold, sum, max, min, count, collect and more.
  • std::collections: HashMap with the entry API, HashSet, BTreeMap and BTreeSet.
  • std::mem::swap, replace and take.
  • std::fmt for Display and Debug impls, std::ops for operator traits and std::cmp::Ordering.
  • From and Into between your own types.
  • TryFrom between integer types.

Duration and Instant are available to iced apps as iced::time::Duration and iced::time::Instant. std::time is not available in plain programs yet.

Not supported yet

These are valid Rust that Rawr rejects today. Each one fails the check with an error that names the construct.

Syntax and items

  • Type aliases (type Id = i64;).
  • Glob imports (use std::collections::*;, use Enum::*;).
  • Restricted visibility such as pub(crate) and pub(super).
  • const fn.
  • Explicit enum discriminants (Red = 1) and casting an enum with as.
  • Byte literals (b'a', b"ab") and char ranges such as 'a'..='e'.
  • macro_rules!, async and .await.
  • A const captured in a format string ("{LIMIT}"). Pass it as an argument instead.

Types and borrowing

  • i128 and u128.
  • Returning &mut from a function or method.
  • Borrowing two fields of one struct mutably at once. swap(&mut p.x, &mut p.y) is one example.
  • &dyn Trait arguments such as &dyn Debug. Box<dyn Trait> works.
  • Dereferencing twice (**x) inside a closure such as the one passed to min_by_key.
  • Comparing an untyped None with <. Comparing typed Option values works.
  • impl Drop.

Standard library

  • Rc, RefCell and Cell.
  • VecDeque and BinaryHeap.
  • std::time in plain programs. iced apps get Duration and Instant from iced::time.
  • std::process::exit and Box<dyn std::error::Error>.
  • write! into a String through std::fmt::Write.
  • Formatter::pad.
  • f64::NAN, f64::INFINITY, f64::MAX, f64::EPSILON, std::f64::consts and f64::rem_euclid.
  • char::from(u8) and char::from_u32. byte as char works.
  • Vec::binary_search.
  • The dbg!, line!, file!, column! and module_path! macros.

Rawr reports one error per check. A file with several unsupported constructs shows them one at a time.

Differences from cargo run

A program that passes both rawr check and rustc usually prints the same output. These are the known cases where it doesn’t.

  • HashMap iteration order. Rawr iterates a HashMap in key order. Rust uses a random order that changes from run to run. Code shouldn’t depend on either.
  • f32 as f64. Rawr keeps the short decimal value. 0.1f32 as f64 prints 0.1 in Rawr and 0.10000000149011612 in Rust. Other f32 arithmetic and printing match.
  • Width on your own Display. Rawr pads the output of a user Display impl to the width in {:>6}. Rust ignores the width unless the impl calls f.pad.
  • TryFrom errors. u8::try_from(300i64) prints Err(()) with {:?}. Rust prints Err(TryFromIntError(PosOverflow)).
  • Panic messages. A panic exits with status 101 in both. Rawr writes the message to stderr as a diagnostic with the source span. Rust writes thread 'main' panicked at ...

Code that Rawr accepts and rustc rejects

Rawr’s check is not rustc. Some code passes rawr check and fails cargo build. Run rawr check --as-rust to find these cases in a project. Commands says what it needs.

  • There is no borrow checker beyond rejecting two live &mut borrows of one value. Use after move, a shared borrow held across a mutation, and returning a reference to a local are all accepted.
  • String and &str are one type to the checker. Passing "x" where a String is expected is accepted.
  • Lifetimes are not checked. A missing lifetime on fn f(a: &str, b: &str) -> &str is accepted.
  • An array reference is accepted where &Vec<T> is expected.
  • Private struct fields can be read and set from another module. Private functions are rejected. rustc rejects them too.
  • HashMap can be used without a use line.
  • Out-of-range literals such as let x: u8 = 300 are accepted.
  • Top-level statements are accepted. Rust allows only items at the top level.
  • In iced code, a concrete widget is accepted where an Element is expected.
