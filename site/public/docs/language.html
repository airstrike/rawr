Supported Rust

rawr checks Rust before it runs it. This page lists the Rust that works today, the largest gaps first. It also lists what is missing, what rawr refuses and the known cases that still differ from cargo run.

At a glance

rawr runs a growing part of Rust. Code that rawr doesn’t support fails the check with an error that names the construct. These are the largest gaps:

  • No macro_rules!, and only the built-in macros.
  • No i128 or u128, and no &mut returned from a function.
  • async code runs only in iced apps under rawr-iced.
  • Part of std. The standard library lists what works.
  • Borrow checking is partial. rawr rejects a use after a move and two live &mut borrows of one value, but accepts some code rustc rejects. rawr check runs cargo check for that reason.

rawr follows Rust’s meaning. Where it can’t yet, it refuses the code. A few known differences remain, and each one is a defect to fix.

How a program runs

rawr checks a whole program before any of it runs. The check resolves names and types, traits and method calls. It also checks that every match covers every case. A program that fails the check doesn’t start.

A program is a Cargo crate or a single .rs file. Run Rust with rawr says which files are interpreted.

A single file can hold items, top-level statements, or both. Top-level statements behave like the body of fn main() { .. }, the way rustdoc runs a doctest, so a function can’t read their variables. rawr runs the top-level statements first and then calls fn main if there is one. Cargo would not build a file with top-level statements, so keep them to snippets and the playground.

This program uses ?, a Result from main and a closure. It prints the same output as the Rust binary and exits with the same status.

parse.rs
fn parse(s: &str) -> Result<i64, String> {
    s.parse::<i64>().map_err(|e| format!("{s:?}: {e}"))
}

fn main() -> Result<(), String> {
    let n = parse("42")?;
    println!("n = {n}");
    let m = parse("forty")?;
    println!("m = {m}");
    Ok(())
}
rawr run parse.rsn = 42 Error: "\"forty\": invalid digit found in string" exit status 1

The exit status is 1. A panic exits with status 101. Rust uses the same statuses.

Items

  • fn. A function can be nested inside another function.
  • struct with named fields, tuple structs and unit structs.
  • enum with unit, tuple and struct variants.
  • impl blocks with methods, associated functions and associated consts. An impl may sit inside a function body. Self works in a method body’s type annotations, as in let next: Self = ...
  • unsafe impl Send for T {} and unsafe impl Sync for T {}. Every value in interpreted code is already Send and Sync, so the impl changes nothing. rawr checks it as rustc does. impl Send without unsafe is an error. So is unsafe impl of another trait.
  • trait with default methods, associated types and static functions. Traits can be implemented for your own types and for built-in types such as i64.
  • const and static items.
  • type aliases, generic ones included, such as type Pair<T> = (T, T);. A pub type can be imported from another module.
  • pub and restricted visibility. pub(crate), pub(super) and pub(in path) all work.
  • mod. A mod util; declaration loads util.rs or util/mod.rs beside the file that declares it. A module whose first line is // rawr is interpreted. A module without that line is native Rust, and cargo builds it. An inline mod m { .. } works too. A path through crate:: or super:: reaches a name that module brings in with use, as in Rust.
  • use with paths and groups, such as use std::collections::{HashMap, HashSet};. A glob of a standard library module such as use std::collections::*; works too. A path that starts with :: names an outside crate, as in use ::image::ColorType;. It is an error when its first name is not a crate.
  • #[derive] of Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash and Default. rawr checks a derive the way rustc does. Deriving Copy on a struct with a String field is an error.

Types

  • Integers: i8, i16, i32, i64, isize, u8, u16, u32, u64 and usize. Overflow panics as it does in a Rust debug build. The wrapping_*, checked_*, saturating_* and overflowing_* methods work.
  • Floats: f32 and f64. Methods such as sqrt, powi, floor, round and trunc work.
  • bool, char, String and &str.
  • Tuples and Vec.
  • Arrays such as [0; 3] and slices such as &v[1..3].
  • Option and Result with their usual methods and the ? operator.
  • Box<T> and Box<dyn Trait>.
  • std::rc::Rc<T> and std::sync::Arc<T>, imported with use. Rc::new, Arc::clone(&a) and .clone() work, and so does .map(Arc::new). Fields and methods reach through them, and &Arc<String> passes where &str is expected. An Rc or Arc is Clone whatever it holds. A value is not copied when one is cloned, as in Rust.
  • impl Trait in argument and return position. This covers impl Fn(i64) -> i64 and impl Iterator<Item = i64>.
  • Function pointers such as fn(i64) -> i64. A function coerces to its pointer type with double as fn(i64) -> i64.
  • as casts between numbers. They truncate and saturate as Rust’s do. u8 as char works too.
  • A fieldless enum casts to an integer with as. Explicit discriminants such as Red = 1 set its values.

Mixing numeric types without a cast is an error, as in Rust. i32 + i64 doesn’t pass the check. Indexing a Vec takes a usize.

Generics and traits

Functions, structs, enums and impl blocks can be generic. Bounds work inline and in where clauses. A generic type without the bound it needs fails the check. rustc rejects it too.

generics.rs
use std::fmt;
use std::ops::Add;

struct Stack<T> {
    items: Vec<T>,
}

impl<T: Clone> Stack<T> {
    fn new() -> Self {
        Stack { items: Vec::new() }
    }

    fn push(&mut self, item: T) {
        self.items.push(item);
    }

    fn top(&self) -> Option<T> {
        self.items.last().cloned()
    }
}

#[derive(Debug, Clone, Copy, PartialEq)]
struct Meters(f64);

impl Add for Meters {
    type Output = Meters;

    fn add(self, other: Meters) -> Meters {
        Meters(self.0 + other.0)
    }
}

impl fmt::Display for Meters {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "{} m", self.0)
    }
}

fn largest<T: PartialOrd + Copy>(items: &[T]) -> T {
    let mut max = items[0];
    for &item in items {
        if item > max {
            max = item;
        }
    }
    max
}

fn main() {
    let mut stack = Stack::new();
    stack.push(Meters(1.5) + Meters(2.0));
    println!("{}", stack.top().unwrap());
    println!("{}", largest(&[3, 9, 2]));
}
rawr run generics.rs3.5 m 9

Trait objects work through Box<dyn Trait>. A Vec<Box<dyn Shape>> can hold different types that implement Shape. Implementing Iterator for your own type gives it map, filter, collect and the other adapters. Implementing FromIterator for your own type lets collect() build it, as in let life: Life = cells.into_iter().collect();. Operator traits from std::ops such as Add work.

Patterns and control flow

  • match with literals, ranges such as 3..=9, alternatives with |, guards and name @ pattern bindings.
  • Struct, tuple and enum patterns. .. matches the rest.
  • Slice patterns such as [first, .., last].
  • if let, while let and let .. else.
  • A let whose pattern is an enum with one variant, such as let Wrapper::Named(x) = value;. Rust accepts it because the pattern can’t fail, and so does rawr.
  • Let chains, as in Rust 2024: if let Some(x) = a && let Some(y) = b && x < y { .. }. while takes them too.
  • loop, while and for. Loop labels work. break can carry a value.
  • Blocks are expressions. let x = { .. }; works.
  • Patterns on &mut places write their bindings back. for p in &mut points { p.x += 1; } changes the elements. So does if let State::Running { progress, .. } = &mut self.state { *progress = p; }. This holds in match, if let, while let, let and let .. else. It holds for nested struct, tuple and slice patterns, for ref mut, for match self in a &mut self method, and for a pattern inside another one.

Moves

A value that is not Copy moves when it is passed, assigned or stored by value, as in Rust. It drops with its last owner. A use after the move fails the check as rustc’s E0382 does. Moving one field out of a struct, as let name = p.name;, leaves the struct’s other fields usable. Assigning the field again makes it usable. A match arm whose pattern binds a part by value moves the subject. a + &b moves the String a.

A let pattern moves each part it binds by value, so let (name, _) = pair; leaves pair.1 usable and pair.0 moved. for x in v moves v. Moving a value out of an index, as let s = v[0];, or out of a field behind a reference fails the check as rustc’s E0507 does. Borrow it or clone it instead.

Cloning an Rc or an Arc gives another handle to the same value. A change through a RefCell inside it shows through every clone, as in Rust.

Closures

Closures capture their environment. move closures work. A closure that mutates what it captures is FnMut. Functions can take closures as impl Fn(..) or as a generic F: Fn(..). They can return them as impl Fn(..) or Box<dyn Fn(..)>. A struct field can hold a Box<dyn Fn(..)>.

A closure in a variable is a value. It can be passed to a function or to map, copied to another variable, or called from inside another closure. A parameter can be _ or another pattern.

A closure’s parameters take their types from where it is passed, as in Rust. A function that takes impl Fn(f32) -> Color gives its closure an f32, so |r| Color { r, ..base } works.

A closure that moves a captured value out, as || drop(s) does, takes that value in when it is made, as in Rust. Such a closure can be called once. A closure that holds a value that is not Copy is not Copy either, so let g = f; moves it.

closures.rs
fn apply(f: impl Fn(i64) -> i64, x: i64) -> i64 {
    f(x)
}

fn scale(k: i64) -> impl Fn(i64) -> i64 {
    move |x| x * k
}

fn main() {
    let mut log = Vec::new();
    let mut add = |line: &str| log.push(line.to_string());
    add("first");
    add("second");
    println!("{:?}", log);
    println!("{} {}", apply(|x| x + 1, 1), scale(3)(2));
    let odd_squares: Vec<i64> = (1..=10).filter(|x| x % 2 == 1).map(|x| x * x).collect();
    println!("{:?}", odd_squares);
}
rawr run closures.rs["first", "second"] 2 6 [1, 9, 25, 49, 81]

Async code

In an iced app under rawr-iced, async fn, async blocks, async closures and .await work. Each .await suspends the body, and it goes on from there with its locals as they were. Async code describes how an app runs them. Other programs can’t use async yet.

Macros

rawr has a fixed set of built-in macros. You can’t define your own with macro_rules!.

MacroNotes
println! print!Write to stdout.
eprintln! eprint!Write to stderr.
format!Builds a String. Takes the same format strings as the print macros.
write!Writes to a Formatter inside a Display or Debug impl.
panic!Stops the program with exit status 101.
assert! assert_eq! assert_ne!Panic when the condition fails. They take an optional message.
debug_assert! debug_assert_eq!Behave as in a Rust debug build.
unreachable! todo! unimplemented!Panic when reached.
vec!Both forms: vec![1, 2] and vec![0; n], where n is any usize expression. An array’s [0; N] takes a literal or a const.
matches!Takes a guard: matches!(x, Some(n) if n > 2).
concat! stringify!Expand to a string literal.
cfg!Tests the machine rawr runs on: target_os, target_arch, target_family, unix and windows, with not, all and any. No feature is on. #[cfg(..)] on a statement leaves it out the same way.
env!Reads an environment variable when the program is checked.
include_str! include_bytes!Read a file relative to the source file.

Format strings

Format strings follow Rust’s rules. All of these work:

  • Positional, numbered and named arguments.
  • Captured variables such as {name}.
  • Fill, alignment, width and precision: {:>8}, {:^7}, {:08.3}, {:.2}.
  • Width and precision from an argument: {:>w$}, {:>1$}, {:.*}.
  • Signs and radix: {:+}, {:#x}, {:X}, {:#b}, {:o}, {:e}.
  • {:?} and {:#?}. Strings and chars are escaped as Rust escapes them.

Hex debug output ({:x?}) is not supported yet.

The standard library

rawr provides part of std. These work today:

  • String and &str: push, push_str, insert, pop, remove, truncate, clear, trim, find, replace, split, splitn, split_whitespace, lines, chars, char_indices, bytes, as_bytes, starts_with, contains, to_uppercase, parse, String::from_utf8 and more. len counts bytes as Rust’s does.
  • Vec and slices: push, pop, insert, remove, retain, extend, dedup, sort, sort_by, sort_by_key, contains, windows, chunks, first, last, resize, resize_with, Vec::with_capacity and more. get_mut and iter_mut().find(..) lend an element, so if let Some(d) = v.iter_mut().find(|d| d.id == id) { d.n += 1; } changes it.
  • Iterators: map, filter, enumerate, zip, skip, take, step_by, rev, any, all, position, fold, sum, max, min, count, collect and more. std::iter::once and std::iter::empty start one. An iterator can be cloned and walked again, as in for c in columns.clone().
  • Arrays: [T; N]::map gives a [U; N].
  • Numbers: abs, pow, sqrt, powi, powf, floor, round and kin. Floats also have sin, cos, tan, their inverses and hyperbolic forms, atan2, hypot, exp, ln, log, log10, to_degrees and to_radians. rem_euclid and div_euclid work on floats and integers. A number’s method can be called by its path, as in f32::rem_euclid(x, 1.0).
  • std::time::Duration and Instant: Duration::from_millis and its kin, as_secs, as_millis, as_secs_f64, Instant::now, elapsed, duration_since, and the operators +, -, *, / and <. {:?} prints Rust’s text, such as 1.5s.
  • std::collections: HashMap with the entry API, HashSet, BTreeMap and BTreeSet. A local may hold an entry, as in let n = map.entry(k).or_default(); *n += 1;. rustc_hash’s FxHashMap and FxHashSet are rawr’s HashMap and HashSet. cargo build still uses the crate’s faster hasher.
  • std::cell::RefCell: new, default, borrow, borrow_mut, into_inner, replace, take and clone. A change through a shared reference to a RefCell changes the cell. A borrow ends with its block, as in Rust. A borrow that conflicts with one still held panics with Rust’s message.
  • std::marker::PhantomData.
  • std::mem::swap, replace and take.
  • std::fmt for Display and Debug impls, std::ops for operator traits and std::cmp::Ordering.
  • From and Into between your own types, and from your own type into a number type such as impl From<Roar> for u32.
  • From::from, Into::into, Clone::clone and ToString::to_string as values. .map(String::from) is one example. A method of Option or Result works as a value too, as in .map(Result::ok). So does an associated function of your own type, as in .map(Db::from) or let make = Db::new;.
  • TryFrom between integer types.

In an iced app, std::time names iced::time’s Duration and Instant, which are std’s own in iced. std::path has PathBuf and Path, and std::ffi has OsString and OsStr. They are Rust’s own types. Path is another name for PathBuf, and OsStr is another name for OsString. They have new, from, push, join, parent, file_name, file_stem, extension, display, to_str and to_string_lossy. An imported Rust function does not take one yet. std::io has Error and ErrorKind. Error::new, Error::other, Error::from and kind work, and {} prints Rust’s text. Nothing in it reads or writes a file.

Not supported yet

These are valid Rust that rawr rejects today. Each one fails the check with an error that names the construct.

Syntax and items

  • A glob import of an enum’s variants (use Shape::*;).
  • const fn.
  • char ranges such as 'a'..='e'.
  • macro_rules!.
  • serde’s #[derive(Serialize, Deserialize)] on your own types.
  • async and .await in a program without iced. iced’s Task is what runs a future, as Async code describes.
  • A const captured in a format string ("{LIMIT}"). Pass it as an argument instead.

Types and borrowing

  • i128 and u128.
  • Returning &mut from a function or method.
  • Borrowing two fields of one struct mutably at once. swap(&mut p.x, &mut p.y) is one example.
  • &dyn Trait arguments such as &dyn Debug. Box<dyn Trait> works.
  • Dereferencing twice (**x) inside a closure such as the one passed to min_by_key.
  • Comparing a None whose type isn’t known yet with <. Comparing Option values of a known type works.
  • impl Drop.

Standard library

  • Cell, Weak and Mutex.
  • std::io beyond Error and ErrorKind, and std::fs.
  • VecDeque and BinaryHeap.
  • std::process::exit and Box<dyn std::error::Error>.
  • write! into a String through std::fmt::Write.
  • Formatter::pad.
  • f64::NAN, f64::INFINITY and f64::EPSILON.
  • char::from(u8) and char::from_u32. byte as char works.
  • Vec::binary_search.
  • The dbg!, line!, file!, column! and module_path! macros.

rawr reports one error per check. A file with several unsupported constructs shows them one at a time.

Differences from cargo run

A program that passes both rawr check and rustc prints the same output, except in these known cases. Each one is a defect to fix, not a rule of the language.

  • HashMap iteration order. rawr iterates a HashMap in key order. Rust uses a random order that changes from run to run. Code shouldn’t depend on either.
  • Width on your own Display. rawr pads the output of a user Display impl to the width in {:>6}. Rust ignores the width unless the impl calls f.pad.
  • TryFrom errors. u8::try_from(300i64) prints Err(()) with {:?}. Rust prints Err(TryFromIntError(PosOverflow)).
  • Panic messages. A panic exits with status 101 in both. rawr writes the message to stderr as a diagnostic with the source span. Rust writes thread 'main' panicked at ...
  • Arithmetic on a generic u64. A u64 or usize above i64::MAX prints and compares as the unsigned number inside a generic function. Adding or multiplying such values there, through T: Add, panics with an overflow once the result passes i64::MAX. Rust gives the result.

Code that rawr refuses rather than run differently

These programs are valid Rust. rawr can’t yet run them with Rust’s meaning, so its check stops with an error that says what isn’t supported.

  • A tokio::select! of two or more branches where a branch’s pattern can fail to match, as Some(n) = receiver.recv() can. tokio would keep waiting on the other branches. Bind the value with value = receiver.recv() and match it in the branch’s body.

Code that rawr accepts and rustc rejects

rawr’s check is not rustc. Some code passes rawr check and fails cargo build. rawr check also runs cargo check, which reports these cases. Commands describes its output.

  • There is no borrow checker beyond rejecting two live &mut borrows of one value and a use after a move. A shared borrow held across a mutation and returning a reference to a local are accepted.
  • String and &str are one type to the checker. Passing "x" where a String is expected is accepted.
  • Lifetimes are not checked. A missing lifetime on fn f(a: &str, b: &str) -> &str is accepted.
  • An array reference is accepted where &Vec<T> is expected.
  • Private struct fields can be read and set from another module. Private functions are rejected. rustc rejects them too.
  • HashMap can be used without a use line.
  • Out-of-range literals such as let x: u8 = 300 are accepted.
  • Top-level statements are accepted. Rust allows only items at the top level.
  • In iced code, a concrete widget is accepted where an Element is expected.
  • .await on an iced Task is accepted. Rust awaits only a future.
  • Returning a field of &self by value, as fn name(&self) -> String { self.name }, is accepted. rustc reports E0507. A let that moves such a field is rejected as rustc rejects it.
