Cargo dependencies

Use the crates in your Cargo.toml and your native modules from marked code. rawr-import compiles them with Cargo.

Install rawr-import

rawr-import runs programs whose Cargo.toml lists dependencies, or which have native modules. Install it and rawr hands those programs to it.

rawr-import needs a Unix system and the pinned Rust nightly nightly-2026-07-11 with the rustc-dev and rust-src components. It has been tested on Apple Silicon Macs.

rustup toolchain install nightly-2026-07-11 --component rustc-dev,rust-src
cargo +nightly-2026-07-11 install --locked --git https://github.com/airstrike/rawr rawr-import-cli
cargo +nightly-2026-07-11 install --locked --git https://github.com/airstrike/rawr rawr-import --features rustc-driver

The rawr-import-cli package installs rawr-import. The rawr-import package installs rawr-import-driver in the same directory. The driver reads the API of your dependencies with the pinned nightly.

rawr-iced imports an iced app’s dependencies the same way. It doesn’t need rawr-import installed.

Project setup

rawr-import builds a runner that links the rawr crate and your dependencies. It builds them in the project’s target/, with the same compiled units cargo build uses. The project needs two files for that:

rust-toolchain.toml
[toolchain]
channel = "nightly-2026-07-11"
components = ["rust-src", "rustfmt", "clippy"]
.cargo/config.toml
[build]
target = "host-tuple"

rust-toolchain.toml pins the nightly, so cargo build uses the same compiler. .cargo/config.toml sets build.target to "host-tuple", so builds go in target/<host>/debug. Then rawr run and cargo build compile each dependency once and share it.

Without the files, rawr run stops with RAWR-ENVIRONMENT-PROJECT-BUILD and prints the files to add. A crate with no dependencies doesn’t need them.

Use a dependency

Declare the dependency in Cargo.toml. Import its items with use. You don’t write bindings.

Cargo.toml
[dependencies]
mathx = { path = "mathx" }
mathx/src/lib.rs
pub fn double(x: i64) -> i64 {
    x * 2
}
src/main.rs
// rawr
use mathx::double;

fn main() {
    for n in 1..=3 {
        println!("{n} doubled is {}", double(n));
    }
}
rawr run1 doubled is 2 2 doubled is 4 3 doubled is 6

The first run compiles the dependencies and the runner. On an Apple Silicon Mac that took about 80 s for this crate. A later run reuses that build. After an edit to src/main.rs, it ran again in about 2.4 s.

rawr uses the dependencies as Cargo resolves them. Workspace inheritance works. A crate under [target.'cfg(..)'.dependencies] counts when its cfg holds on your machine. rawr reads only the items your code uses.

Native modules

A module of your crate whose first line isn’t // rawr is native Rust. rawr-import compiles it with Cargo, and marked code calls it as it calls a dependency. Native code must not use code from marked files yet. rawr reports an error if it does.

Imported values

A struct in a marked file can hold a value of an imported type. It can #[derive(Default)] when the crate implements Default for that type. The field then takes the crate’s default(), as in Rust. It can also derive Debug, Clone and Copy when the crate implements them for that type. == and != compare two imported values when the crate implements PartialEq for their type. An imported value can key a HashMap or a HashSet when the crate implements Hash and Eq for its type. {:?} of an imported value prints the crate’s Debug text. to_string() and {} of an imported value print its Display text. A Message can hold an imported value, and a match can bind it.

A Rust method that takes a &str takes a string from interpreted code. A method whose result rawr cannot hold returns that result’s Display text instead, when its type has one. So chrono’s now.format("%H:%M:%S") is a String.

An imported type written without its defaulted type arguments takes their defaults, as in Rust. So palette’s Hsl is Hsl<Srgb, f32>. A default that rawr cannot name, such as iced’s renderer in text_editor::Content, still has to be written.

A Rust function or method that returns a Vec, a slice or a tuple gives a rawr Vec or tuple. An immutable static of a slice or a number reads as its value, as preset::ALL does for pub static ALL: &[Preset] = &[..]. Its elements are cloned out of the slice. Rust functions still cannot take a Vec, a slice or a tuple from rawr.

A field of an imported type that is Copy reads as a copy, as in Rust. .clone() of an imported value leaves the original usable, as in Rust.

A match or if let can match a variant of an imported enum, as in echo::Event::Connected(connection) => ... The pattern takes the variant’s fields as clones. A path through a native module, such as download::Progress in a field, names the type even beside a function called download.

Known gaps

  • A program that rawr-import runs exits with status 1 when it fails, a panic included. Rust would exit with 101.
  • rawr-import runs a program once. It doesn’t watch for saves yet.
  • A method that is generic over a sealed trait, such as itoa::Buffer::format, can’t be called yet.
