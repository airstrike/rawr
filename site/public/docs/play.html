//?play and the playground

?play and the playground

The ?play bot runs a Rawr snippet posted in Discord and replies with the result. The playground does the same in a browser. Neither needs anything installed.

In Discord

Write ?play on the first line of a message and put the snippet in a code block below it. The fence can be ```rust or a bare ```. The bot also answers when ?play is in the fence’s info string, as in ```rust ?play.

Discord
?play 320x200 light msg=Message::Increment
```rust
column![text("hi"), button("go")]
```

The bot runs the first code block in the message. A snippet that uses iced gets an image of its rendered frame. A plain program gets its output in a text block. An error gets the report that rawr check would print. The report names the snippet play.rs. The bot cuts it to 2000 characters.

If you edit a message the bot already answered, it runs the snippet again and edits its reply. The bot ignores messages from other bots.

Options

Options go on the ?play line after the command.

OptionMeaning
WxH or size=WxHThe canvas size in logical pixels. Each side can be at most 2048. Without a size the canvas fits the content. It adds a 12 px margin.
dark, light or theme=..The theme to render with. The default is dark. An app with its own .theme(..) uses its own theme.
msg=EXPRA message to apply before rendering. Repeat it to apply several in order.

Images are drawn at twice the logical size, so they stay sharp on high-density screens.

Snippet shapes

A snippet uses iced when it names the iced crate. It also uses iced when it uses one of iced’s widget functions, widget macros or common types without declaring or importing it. column!, text, button, Color and Fill are examples. Every other snippet is a plain program.

An expression

A bare iced expression renders as a view.

column![text("hi"), button("go")]

A view

A function named view with no arguments renders what it returns.

fn view() -> impl Widget<()> {
    row![text("left"), text("right")].spacing(20)
}

Expressions and views without use lines get those iced names imported for them. Messages are refused for expressions and views. Only an app takes them.

An app

A type with fn view(&self) and fn update(&mut self, message) is an app. The snippet can have its own main with iced::run or iced::application. Without one, the bot boots State::default(). It applies each msg= in order and then renders the view. A main whose iced::run takes closures, such as iced::run(|n: &mut u32, _: Message| *n += 1, |n: &u32| text(n)), is an app too, with no fn view. An app doesn’t get imports for free. Write its use lines as you would in a file.

?play light msg=Message::Increment msg=Message::Increment
use iced::widget::{Widget, button, column, text};

#[derive(Default)]
struct Counter {
    value: i64,
}

#[derive(Debug, Clone, Copy)]
enum Message {
    Increment,
}

impl Counter {
    fn update(&mut self, message: Message) {
        match message {
            Message::Increment => self.value += 1,
        }
    }

    fn view(&self) -> impl Widget<Message> {
        column![
            text(self.value).size(40),
            button("Increment").on_press(Message::Increment),
        ]
        .padding(20)
    }
}

A snippet with its own #[preview] is refused. Use the size option instead.

A plain program

A plain program runs the way rawr run runs a file. Its top-level statements run first. Then fn main runs if there is one. The reply is its stdout and stderr in the order it wrote them.

A snippet of statements alone runs as the body of main. If its last expression has no semicolon, its value is printed with {:?}. So 1 + 2 prints 3, and 1 + 2; prints nothing.

let xs = vec![3, 1, 2];
xs.iter().sum::<i64>()
6

The reply shows the exit status when it isn’t 0. A main that returns Err prints Error: .. and exits with status 1. A panic exits with status 101. A program stopped by a limit exits with status 1. Messages don’t apply to a plain program. The reply notes that they were ignored.

When the frame is taken

An app is rendered as iced would first show it. Its boot task runs and the messages are applied. Then the view is drawn over a sequence of frames until it settles.

  • A frame where a widget publishes a message applies that message and draws again.
  • A frame that changes the interface draws again. A component handling its own event is one example. A sensor firing is another.
  • A frame that changes nothing settles. If a widget asked to be redrawn at a later time, the clock jumps to that time and drawing continues.
  • An animation that asks for the very next frame settles right away.
  • At most 8 frames are drawn.

Subscriptions don’t run, so a timer never ticks. Use msg= to put the app in the state you want to show.

Limits

Snippets are untrusted. Each one runs in its own process with these limits on the hosted bot and playground:

LimitValue
Script time5 seconds. The whole run is stopped after 10 seconds.
Memory256 MB per run.
Operations1,000,000 per evaluation.
Call depth32.
ValuesStrings up to 64 KiB. Arrays up to 65,536 elements. Maps up to 10,000 entries.
Output64 KiB. Longer output ends with … output truncated. Discord replies are also cut to fit a message.
Canvas2048 logical pixels per side.

A limit gets a plain reply such as time limit exceeded. Snippets have no filesystem, network or environment access.

Images without files

?play has no files. An image or svg path draws as a missing file. include_str! and include_bytes! fail with an error that says so. A snippet can still draw an image from bytes it holds. svg::Handle::from_memory takes svg text as bytes. image::Handle::from_bytes takes the bytes of a PNG or JPEG file. image::Handle::from_rgba takes a width, a height and 4 bytes for each pixel.

circle.rs
let circle = r#"<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 100 100">
  <circle cx="50" cy="50" r="40" fill="hotpink"/>
</svg>"#;

svg(svg::Handle::from_memory(circle.as_bytes())).width(160).height(160)
(draws a pink circle)

The bot also limits how often it runs. Each user gets 4 runs a minute. Each channel gets 12. A run over the limit gets an hourglass reaction instead of a reply.

The playground

rawr.airstrike.fyi/play has an editor and an output pane. Ctrl+Enter or Cmd+Enter runs the code. Tab indents. You can pick the theme and a size. The messages box takes one Message expression per line.

The Examples menu loads some of iced’s own examples. Examples → Reset brings back the counter. The editor keeps your latest snippet in the browser, so /play opens where you left off.

Each visitor gets 6 runs a minute and 60 an hour. Code can be up to 16 KiB. A run takes up to 32 messages.

Share links

Share saves the code and options and gives a link of the form /play/<id>. The id comes from the content, so the same snippet always gets the same link. A shared snippet can be up to 64 KiB.

A shared link shows a preview card when posted in Discord and other apps. For an iced snippet the card is its first frame. For a plain program it is the site card with the first line of output. A share that nobody opens for 30 days is deleted.

Adding the bot to a server

Use the invite link to add the bot to a Discord server you manage. The bot answers only in channels a moderator turns on. It doesn’t answer in direct messages.

Moderators choose the channels with the /play-channel command. It needs the Manage Channels permission in the channel it changes. Its replies are visible only to the moderator who ran it.

CommandWhat it does
/play-channel add [channel]Turns the bot on in a channel. The default is the current channel.
/play-channel remove [channel]Turns the bot off in a channel.
/play-channel listLists the channels where the bot answers.

A thread follows its parent channel. Running /play-channel add in a thread turns the bot on for the parent channel.

The status page shows whether the bot is up. It also counts recent runs.
