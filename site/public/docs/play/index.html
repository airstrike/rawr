Play

The playground runs Rust code in your browser and shows its output. It renders iced code as an image or an animation. No installation is required.

The editor

rawr.airstrike.fyi/play has an editor and an output pane. Ctrl+Enter or Cmd+Enter runs the code. Tab indents. You can pick the theme and a size. The messages box takes one Message expression per line.

The Examples menu loads iced’s own arc, checkbox, combo box, component, counter, custom quad, custom widget, lazy, modal, progress bar, QR code, sandpiles, scrollable, slider, stopwatch, styling, table, text, tooltip and vectorial text examples. Examples → Reset brings back the counter. The editor keeps your latest snippet in the browser, so /play opens where you left off.

Each visitor gets 6 runs a minute and 60 an hour. Code can be up to 16 KiB. A run takes up to 32 messages, and each message can be up to 256 bytes. The playground uses the same renderer as the bot, with the same limits and allowance. Discord runs go first. When the renderer is busy for too long, the playground says the playground is busy; try again in a moment.

Share links

Share saves the code and options and gives a link of the form /play/<id>. The id comes from the content, so the same snippet always gets the same link. A shared snippet can be up to 64 KiB.

A shared link shows a preview card when posted in Discord and other apps. For an iced snippet the card is its last frame. For a plain program it is the site card with the first line of output. A share that nobody opens for 30 days is deleted.

Snippet shapes

A snippet uses iced when it names the iced crate. It also uses iced when it uses a name from rawr-iced’s prelude without declaring or importing it. column!, text, button, Color and Fill are examples. Every other snippet is a plain program.

An expression

A bare iced expression renders as a view.

column![text("hi"), button("go")]

A view

A function named view with no arguments renders what it returns.

fn view() -> impl Widget<()> {
    row![text("left"), text("right")].spacing(20)
}

Expressions and views can’t take messages. Only an app takes them.

An app

A type with fn view(&self) and fn update(&mut self, message) is an app. The snippet can have its own main that calls iced::run or iced::application. Without one, the bot boots State::default(). A main whose iced::run takes closures is an app too. iced::run(|n: &mut u32, _: Message| *n += 1, |n: &u32| text(n)) is one example. It needs no fn view.

The bot applies each msg= in order. Output says what the reply shows. An app doesn’t get imports for free. Write its use lines as you would in a file.

?play light msg=Message::Increment msg=Message::Increment
use iced::widget::{Widget, button, column, text};

#[derive(Default)]
struct Counter {
    value: i64,
}

#[derive(Debug, Clone, Copy)]
enum Message {
    Increment,
}

impl Counter {
    fn update(&mut self, message: Message) {
        match message {
            Message::Increment => self.value += 1,
        }
    }

    fn view(&self) -> impl Widget<Message> {
        column![
            text(self.value).size(40),
            button("Increment").on_press(Message::Increment),
        ]
        .padding(20)
    }
}

A snippet with its own #[preview] is refused. Use the size option instead.

A plain program

A plain program runs the way rawr run runs a file. Its top-level statements run first. Then fn main runs if there is one. The reply is its stdout and stderr in the order it wrote them.

A snippet of statements alone runs as the body of main. If its last expression has no semicolon, its value is printed with {:?}. So 1 + 2 prints 3, and 1 + 2; prints nothing. A last value whose type has no Debug runs and isn’t printed.

let xs = vec![3, 1, 2];
xs.iter().sum::<i64>()
6

The reply shows the exit status when it isn’t 0. A main that returns Err prints Error: .. and exits with status 1. A panic exits with status 101. A program stopped by a limit exits with status 1. Messages don’t apply to a plain program. The reply notes that they were ignored.

What a snippet can reach

A snippet runs on rawr’s server in a sandbox. It has no files, no environment variables and no network, and it runs under time and memory limits. It can use rawr’s std, iced and a stand-in for tokio, and no other crates. The hosted execution reference has the details.
