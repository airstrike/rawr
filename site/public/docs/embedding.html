Embedding

A second use of rawr: your app runs Rust scripts while it runs. It exports its own types and functions with #[rawr::export], compiles a script with an Engine and calls the functions the script defines.

Add the crate

The crate needs Rust 1.95 or newer.

cargo add --git https://github.com/airstrike/rawr rawr

Export your types

Put #[rawr::export] on a struct, on its impl block and on a free function. This is examples/app in the repository, an app with its own Cargo workspace.

examples/app/src/main.rs
use rawr::{Engine, Exports, Scope};

#[derive(Clone)]
#[rawr::export]
pub struct Order {
    pub customer: String,
    pub items: i64,
}

#[rawr::export]
impl Order {
    pub fn total(&self, price: f64) -> f64 {
        price * self.items as f64
    }

    pub fn add(&mut self, n: i64) {
        self.items += n;
    }
}

#[rawr::export]
fn tax_rate(state: &str) -> f64 {
    if state == "NY" { 0.08875 } else { 0.0 }
}

fn main() -> Result<(), Box<rawr::EvalAltResult>> {
    // Scripts are named relative to the app, as rustc names source files.
    std::env::set_current_dir(env!("CARGO_MANIFEST_DIR")).expect("the app's directory");
    let script = std::env::args().nth(1).unwrap_or("scripts/pricing.rs".into());

    let mut shop = Exports::new("shop");
    shop.add::<Order>().add::<tax_rate>();
    let mut engine = Engine::new();
    engine.export(shop)?;

    let ast = engine.compile_file(script.into())?;
    let mut scope = Scope::new();

    let total = engine.call_fn::<f64>(&mut scope, &ast, "price", (100.0_f64, 2_i64))?;
    println!("{total:.2}");
    let receipt = engine.call_fn::<String>(&mut scope, &ast, "receipt", (100.0_f64, 5_i64))?;
    println!("{receipt}");

    let order = Order { customer: "Ada".into(), items: 2 };
    let label = engine.call_fn::<String>(&mut scope, &ast, "label", (order.clone(),))?;
    println!("{label}");
    let bigger = engine.call_fn::<f64>(&mut scope, &ast, "bigger", (order,))?;
    println!("{bigger:.2}");
    Ok(())
}

The script imports the exports from the root the app named, as Rust code imports from a crate. It reads the pub fields and calls the methods as Rust would.

examples/app/scripts/pricing.rs
use shop::{tax_rate, Order};

fn price(subtotal: f64, items: i64) -> f64 {
    let rate = tax_rate("NY");
    let shipping = if items > 3 { 0.0 } else { 4.99 };
    subtotal * (1.0 + rate) + shipping
}

fn receipt(subtotal: f64, items: i64) -> String {
    format!("{items} items, {:.2} total", price(subtotal, items))
}

fn label(order: Order) -> String {
    format!("{} x{}", order.customer, order.items)
}

fn bigger(mut order: Order) -> f64 {
    order.add(3);
    price(order.total(10.0), order.items)
}
cargo run113.87 5 items, 108.88 total Ada x2 54.44

On a struct, #[rawr::export] exports the type and its pub fields. A script reads a field and assigns it. On the impl block, it exports the pub methods and associated functions. A method keeps its receiver, so a script calls add, which takes &mut self, only on a mut binding. On a free function, it exports the function. Private fields and methods stay private. As in Rust, a field and a method may share a name. order.items reads the field, and calling a field or reading a method without parentheses is rustc’s error.

Exports::new names the root that scripts use. add takes each exported struct and function by name. Engine::export installs them. Export everything before you compile a script that uses the exports. After that compile, the exports can’t change, and Engine::export returns an error. Scripts on one engine share its exports. Use another Engine for another set.

The first release exports one impl block per struct. It doesn’t export generic items, &mut parameters or functions that return a reference.

A script without exports

This is examples/cart.rs in the repository. It compiles examples/scripts/cart.rs and calls its main. That script is the cart program from Get started without its // rawr line. A script is typed Rust, like every program rawr runs. An embedded script doesn’t need the marker. Engine::compile takes text, so the file’s name is the app’s choice. The examples use .rs.

examples/cart.rs
use rawr::{Engine, Scope};

fn main() -> Result<(), Box<rawr::EvalAltResult>> {
    let engine = Engine::new();
    let ast = engine.compile(include_str!("scripts/cart.rs"))?;
    engine.call_fn::<()>(&mut Scope::new(), &ast, "main", ())
}
cargo run --example carttotal: 27

Engine::compile parses and checks the source. It returns an AST. If the source doesn’t pass the check, it returns an error. call_fn runs a function from that AST and converts its result to the type you name. A Scope holds variables that live across calls.

Statements and expressions

A script can be items, as above, or plain statements. Statements run as if they were the body of fn main() { .. }, the way rustdoc runs a doctest. The value of the last expression is what Engine::eval returns. Functions in the script can’t read its let variables, as in Rust.

src/main.rs
use rawr::{Engine, Scope};

fn main() -> Result<(), Box<rawr::EvalAltResult>> {
    let engine = Engine::new();
    println!("{}", engine.eval::<i64>("40 + 2")?);
    println!("{}", engine.eval::<i64>("fn double(x: i64) -> i64 { x * 2 } double(21)")?);

    let mut scope = Scope::new();
    scope.push("count", 40_i64);
    engine.run_with_scope(&mut scope, "count += 2;")?;
    println!("{}", scope.get_value::<i64>("count").unwrap());
    Ok(())
}
cargo run42 42 42

A value pushed into a Scope becomes a typed variable in the script’s scope. Its type comes from its value. An i64, f64, bool, char or string has that type. A constant from push_constant can’t be assigned. Engine::eval_expression takes one expression and refuses statements.

Calling functions

Arguments go in a tuple. A function with one argument takes a one-element tuple such as (x,). A function with none takes (). The type parameter of call_fn is the return type.

src/main.rs
use rawr::{Engine, Scope};

const SCRIPT: &str = r#"
fn add(a: i64, b: i64) -> i64 {
    a + b
}

fn greet(name: String) -> String {
    format!("hello, {name}")
}

fn mean(xs: Vec<f64>) -> f64 {
    let mut sum = 0.0;
    for x in &xs {
        sum += *x;
    }
    sum / (xs.len() as f64)
}
"#;

fn main() -> Result<(), Box<rawr::EvalAltResult>> {
    let engine = Engine::new();
    let ast = engine.compile(SCRIPT)?;
    let mut scope = Scope::new();

    let n = engine.call_fn::<i64>(&mut scope, &ast, "add", (2_i64, 40_i64))?;
    let s = engine.call_fn::<String>(&mut scope, &ast, "greet", ("Rust".to_string(),))?;
    let xs: rawr::Array = vec![1.0_f64.into(), 2.0_f64.into(), 4.5_f64.into()];
    let m = engine.call_fn::<f64>(&mut scope, &ast, "mean", (xs,))?;

    println!("{n} {s} {m}");
    Ok(())
}
cargo run42 hello, Rust 2.5

Calling a function that doesn’t exist returns an error (Function not found: nope). So does asking for the wrong return type (Output type incorrect: string (expecting i64)).

What crosses the boundary

Your appThe script
i64, f64, bool, charThe same types. Pass integers as i64 and floats as f64.
String, &strEither one can be passed for a String or &str parameter. A returned string comes back as String.
rawr::ArrayA Vec. Build one from values converted with .into().
()The unit return of a function such as main.
rawr::DynamicAny value. A struct or enum that the script defines comes back as a Dynamic. Rust code can hold it and pass it back. It can’t read the fields.

An exported struct crosses as itself. A script gets the Rust value, and Rust gets back the value the script returns. The exported items take and return i64, f64, bool, char, String, (), Option of these and exported structs. A parameter may borrow, as &str or &Order does.

The check knows the items exported to the engine that compiles the script. A call to any other name is an unknown function error at the name, as in rustc.

Capturing output

By default println! and print! write to the process’s stdout. eprintln! and eprint! write to stderr. Engine::on_output sends that text to a callback instead. The callback gets the stream and the exact text. println! text includes its newline.

src/main.rs
use std::sync::{Arc, Mutex};
use rawr::{Engine, Output, Scope};

fn main() -> Result<(), Box<rawr::EvalAltResult>> {
    let mut engine = Engine::new();
    let lines = Arc::new(Mutex::new(Vec::new()));
    let sink = lines.clone();
    engine.on_output(move |output, text| {
        sink.lock().unwrap().push((output == Output::Stderr, text.to_string()));
    });

    let ast = engine.compile(r#"
        fn main() {
            println!("to stdout");
            eprintln!("to stderr");
        }
    "#)?;
    engine.call_fn::<()>(&mut Scope::new(), &ast, "main", ())?;
    println!("{:?}", lines.lock().unwrap());
    Ok(())
}
cargo run[(false, "to stdout\n"), (true, "to stderr\n")]

Loading and reloading scripts

The Engine doesn’t read or watch files on its own. Your app decides when to load a script.

  • compile_file reads a script and checks it against the exports. compile does the same with text.
  • The AST it returns stays valid. Call call_fn on it as often as you like.
  • To pick up an edited script, call compile_file again and call functions on the new AST. The old one keeps working until you drop it.
  • A Scope holds variables across calls. Your app chooses whether a new AST gets the old Scope or a new one.

In a release build

An app that runs scripts ships the rawr crate, because the interpreter runs the scripts at run time. This differs from the dev loop, where Cargo compiles the marked files and no interpreter ships.

Errors

A compile error prints as rustc prints one, with its code, the message and the source line. Display prints it. So does the Debug output that fn main() -> Result shows when ? returns the error. compile_file names the file. compile names the source <script>. Run examples/app with a typo in its script:

cargo run -- scripts/typo.rsexit 1
Error: error[E0609]: no field `itmes` on type `Order`
 --> scripts/typo.rs:4:45-4:50
 4 |     format!("{} x{}", order.customer, order.itmes)
   |                                             ^^^^^

compile returns Result<AST, ParseError>. compile_file, eval, run_with_scope and call_fn return Result<_, Box<EvalAltResult>>. In a function that returns Box<EvalAltResult>, ? converts a ParseError, as the examples on this page do.

To match on a compile error, call err_type() on the ParseError. A runtime error from call_fn names the problem and its position in the script.

Limits

An Engine can bound what a script may do. Set the limits on the engine before running a script.

  • set_max_operations stops a script after a number of steps. An endless loop then fails with Too many operations.
  • set_max_call_levels bounds recursion depth.
  • set_max_string_size, set_max_array_size and set_max_map_size bound the size of values.
  • on_progress runs a callback as the script runs. Returning Some(value) from it stops the script. A host can use it for a wall-clock deadline.

The playground and the ?play bot use these limits for untrusted snippets.
