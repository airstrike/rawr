Reload

Saving a marked file swaps its new code into the running iced app. The app keeps its state when the new code allows it.

Saving a marked file

A save checks the new code and swaps it in with no native build. In a gallery app on an Apple Silicon Mac, that took about 0.2 s.

rawr run also runs cargo check in the background. Its errors show in a card at the top of the window and on stderr. They don’t block the reload.

What a reload keeps

A change to the state’s own types can make the old state incompatible. Then the app boots again.

A Duration and an Instant in the State survive a restart of the app’s runner. A Duration carries exactly. An Instant carries as its distance from the present, so a running stopwatch keeps its elapsed time.

A text_editor::Content in the State survives an edit to a marked file. The editor keeps its text, its cursor and its undo history. A restart of the runner starts it again from the State’s boot. A combo_box::State holds the code that labels its options, so it doesn’t survive an edit.

A value of an imported type in the State survives an edit to a marked file. An edit to the dependency’s Rust code starts a new app from its default State. The window names the imported type that did not carry over.

A save that fails the check

The last good code keeps running. A bar in the window shows the error. Its buttons retry, copy the error or reset the app.

Native edits

Saving a native module or a dependency’s source rebuilds it with Cargo. The app reloads when the build finishes. In the same gallery app on a busy Apple Silicon Mac, that took about 8 s.

Tasks and async code

A reload cancels the running tasks. Their handles report is_aborted(), and the status line says so. A suspended async body never goes on with the new code.

The State keeps what it held. A download the reload cancelled still shows as running until a message changes it.

A reload drops the output of a spawn_blocking closure that is still running. It can’t stop the thread, which ends when the closure returns.

Statements before the app

main may run statements such as tracing_subscriber::fmt::init(); before the app starts. They run once, when rawr run starts. A reset or a reload boots the app again without them. An edit to them takes effect when rawr run restarts, and the window says so.
