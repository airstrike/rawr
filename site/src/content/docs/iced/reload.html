Reload

Saving a marked file reaches the running iced app at its next message. The app keeps its state when the new code allows it.

Saving a marked file

An iced app’s marked main hands control to iced’s event loop. iced calls your update and view back, so a save reaches the app as A running marked main describes.

  • A save applies at the next message, with the state kept.
  • iced builds the view again when a message arrives, so until then the window shows the last view.
  • A struct or enum with new fields or variants restarts the app, since iced may hold a value of the old shape.
  • An edit to main restarts the app, since main runs only once.
  • An edit to a native file or to Cargo.toml rebuilds it with Cargo and restarts the app.

One line on stderr says why the app restarted.

A save that fails the check

The save prints its error, and the last good code keeps running.

rawr run also runs cargo check beside the app. Checking says when its errors are printed.
