iced

rawr-iced runs an iced app with its marked files interpreted. Saving a marked file reloads that code while the app keeps running.

When rawr-iced is used

The rawr command hands a program to rawr-iced when it names the iced crate and rawr-iced is installed. rawr-iced imports the app’s other crates as rawr-import does. Set RAWR_VERBOSE=1 to see which runner a program went to.

rawr-iced is built against iced master at revision be88873d, which rawr doctor prints. A project on another revision is refused.

Without rawr-iced

With rawr-iced not installed, rawr run hands an iced app to rawr-import, which runs it as it runs any crate. It reads iced’s API and generates the bindings your marked files call. Nothing in rawr is written for iced.

Your main calls iced’s own iced::run(update, view) or iced::application(..).run(), as an ordinary generic call. iced runs the event loop, the window and the drawing. Your State and Message cross into it as Rust types of their own, named as you name them, so the window’s title is iced’s default for your crate. Your update and view cross as Rust functions the runner makes, which call the version of your code that is current. Generic items says how.

What works today:

  • iced’s counter, checkbox, slider, tooltip, pick_list and url_handler examples run unchanged but for the // rawr line, with the title, the theme and the widgets cargo run gives them.
  • iced::application(..).subscription(App::subscription) takes your method, which iced calls with your state. Tasks work as iced gives them, so update can return Task::none() or window::latest().and_then(window::close).
  • A save of a marked file applies at the next message, with the state kept. iced builds the view again when a message arrives, so until then the window shows the last view.
  • A function of iced’s that gives an impl Widget or an impl Program, as iced::widget::iced(..) and iced::application(..) do, works as a value you pass on to iced.
  • Most of iced’s other examples stop with an error at a gap rawr-import doesn’t fill yet.
  • Previews, widget reload and the window tools for agents come from rawr-iced.

Install

rawr-iced needs 64-bit macOS or 64-bit Linux and the pinned Rust nightly nightly-2026-07-11 with the rustc-dev and rust-src components. It has been tested on Apple Silicon Macs. Install the rawr command first.

rustup toolchain install nightly-2026-07-11 --component rustc-dev,rust-src
cargo +nightly-2026-07-11 install --locked --git https://github.com/airstrike/rawr rawr-iced-cli
cargo +nightly-2026-07-11 install --locked --git https://github.com/airstrike/rawr rawr-import --features rustc-driver

The last line installs rawr-import-driver, which reads the API of iced and your other dependencies.

The iced template

rawr new counter --template iced && cd counter && rawr run

counter is an ordinary Cargo crate. Its Cargo.toml depends on iced at the revision rawr-iced is built against. The features turn on every widget rawr-iced supports.

Cargo.toml
[package]
name = "counter"
version = "0.1.0"
edition = "2024"

[dependencies]
iced = { git = "https://github.com/iced-rs/iced", rev = "be88873d38544455e26c7a104eb757da2cbbac6b", features = ["advanced", "canvas", "image-without-codecs", "qr_code", "selector", "sipper", "svg"] }

rawr run and cargo build share one build of iced, with no other file. Your own cargo builds rawr’s runner with the project’s toolchain and config, in the project’s target/. Imports explains it.

src/main.rs is iced’s own counter example with // rawr as its first line.

src/main.rs
// rawr
use iced::Center;
use iced::widget::{Widget, button, column, text};

pub fn main() -> iced::Result {
    iced::run(Counter::update, Counter::view)
}

#[derive(Default)]
struct Counter {
    value: i64,
}

#[derive(Debug, Clone, Copy)]
enum Message {
    Increment,
    Decrement,
}

impl Counter {
    fn update(&mut self, message: Message) {
        match message {
            Message::Increment => {
                self.value += 1;
            }
            Message::Decrement => {
                self.value -= 1;
            }
        }
    }

    fn view(&self) -> impl Widget<Message> {
        column![
            button("Increment").on_press(Message::Increment),
            text(self.value).size(50),
            button("Decrement").on_press(Message::Decrement)
        ]
        .padding(20)
        .align_x(Center)
    }
}
rawr run(opens a window)

cargo run compiles the same app natively. A release build doesn’t need the interpreter.

The first rawr run compiles iced and the runner in the project’s target/. On an Apple Silicon Mac that took about 2 minutes. Later runs reuse the build. Reload covers what a save does.

App shapes

iced::run

iced::run(State::update, State::view) boots State::default(), as the counter does. The state can be any type with a Default.

update and view can be closures, as in iced::run(|n: &mut u32, _: Message| *n += 1, |n: &u32| text(n)). Each parameter needs its type. An untyped one fails the check. An update closure returns () unless it declares a return type such as -> Task<Message>.

The application builder

iced::application(boot, update, view) takes a boot function such as State::default. It accepts these builders:

  • .title(..) with a method of the state or a string literal.
  • .theme(..) with a method that returns a Theme, or with a theme such as Theme::Dark.
  • .subscription(..) with a method that returns a Subscription.
  • .centered().

.window_size(..), .font(..), .style(..) and other window and renderer settings are accepted. rawr-iced doesn’t apply them yet.

The chain may come from a function of your own, as in iced’s todos example. fn application() -> Application<impl Program<Message = Message, Theme = Theme>> returns it, and main ends with application().run(). main must be that function’s only caller.

This app uses the builder and an update that returns a Task:

src/main.rs
// rawr
use iced::widget::{Column, Widget, button, column, row, text, text_input};
use iced::{Element, Fill, Task};
use rawr::preview;

pub fn main() -> iced::Result {
    iced::application(Todos::default, Todos::update, Todos::view)
        .title("Todos")
        .run()
}

#[derive(Default)]
struct Todos {
    draft: String,
    items: Vec<String>,
}

#[derive(Debug, Clone)]
enum Message {
    Edit(String),
    Add,
    Remove(usize),
}

impl Todos {
    fn sample() -> Todos {
        Todos {
            draft: String::new(),
            items: vec!["Write the docs".to_string(), "Ship them".to_string()],
        }
    }

    fn update(&mut self, message: Message) -> Task<Message> {
        match message {
            Message::Edit(draft) => self.draft = draft,
            Message::Add => {
                if !self.draft.is_empty() {
                    self.items.push(self.draft.clone());
                    self.draft.clear();
                }
            }
            Message::Remove(index) => {
                self.items.remove(index);
            }
        }
        Task::none()
    }

    #[preview(name = "two items", seed = Todos::sample, size = (360, 180))]
    fn view(&self) -> impl Widget<Message> {
        let items: Vec<Element<'_, Message>> = self
            .items
            .iter()
            .enumerate()
            .map(|(index, item)| {
                row![text(item).width(Fill), button("x").on_press(Message::Remove(index))]
                    .spacing(8)
                    .boxed()
            })
            .collect();
        column![
            text_input("What needs doing?", &self.draft)
                .on_input(Message::Edit)
                .on_submit(Message::Add),
            Column::with_children(items).spacing(4),
        ]
        .spacing(12)
        .padding(16)
    }
}

use rawr::preview; comes from the rawr-macros dependency, as Previews describes.

Timed applications

iced::application::timed(boot, update, subscription, view) passes update the Instant of each message, as in fn update(&mut self, message: Message, now: Instant). An animation can then read time from its messages and never call Instant::now() in update.

The subscription is the third argument. A .subscription(..) after it fails the check. The other builders above work as they do on iced::application.

Under rawr run, the Instant is the present when the message reaches update. ?play reads it from the recording’s clock instead. An animation there moves by the recording’s frame times, so it renders the same on every run.
