Native boundary

How native code and the marked modules of one crate name each other, and what crosses between them.

Run’s A native main sums this page up in two tables. Its Limits today lists what doesn’t cross yet.

Names on each side

Native code sees the public items of a marked module. Those are its functions, methods, structs, enums, traits, constants, statics and type aliases. Each function that native code can call gets a trampoline with the same signature. Private items stay in the interpreter. A native module below a marked one is the exception, since Rust lets a module see its ancestors’ private items. Each private item that such a module names gets a trampoline or a copy as well.

A marked module names native items as Rust lets any module of the crate name them. It names every item of the native crate root, as a Rust module names its parent’s items. With enum Message, type Event = page::Message and fn helper in main.rs, a marked module declared there writes crate::Message::Page(i, page::Message::Noop), let event: crate::Event and super::helper(). A use in main.rs is reached as crate::Name. A marked module deeper in the tree names the private items of its native parent the same way.

A marked module also names the public items of your other native modules. With pub trait Page, pub fn scale and pub mod size in a native page.rs, a marked module writes crate::page::scale(2) and use crate::page::size::Width;. It writes Box<dyn page::Page> after use crate::page; and Box<dyn Page> after use crate::page::Page;.

In rawr’s copy of the crate, the items of the root and of each native module on the way to a marked one are public. That is how the interpreter reaches them. Your files stay as they are.

How values cross

Numbers, bool, char, String and &str cross between native code and a marked module. Vec, Option, Result and tuples of them cross too. So do the structs and enums of marked modules whose fields cross. A call copies these values. A native value inside one of them moves with it, or is lent where it is when the argument is a borrow.

A function may also return a value of a native type. The type may be one your native code declares, such as the Message in your main.rs, or another crate’s. It may be bare, or inside a Vec, an Option, a tuple or a Result, or an alias of one such as iced::Result. The native value itself goes back to native code, so fn main() -> iced::Result gets iced’s own error. A type with a lifetime, such as iced::Element<'a, Message>, comes back too. The value is the interpreter’s own, so it borrows nothing. It takes the lifetime the signature names.

A parameter may be one of those values or a reference to one. A &mut argument comes back with the changes the function made. A native value taken by value moves to the function. The function keeps it as Rust would. It may be bare, or inside a Vec, an Option, a Box or a tuple, such as grid: Option<Element<'a, Message>>. A native value whose type has a lifetime, such as a View<'a> of borrows, is the function’s for the call alone. Rust lets the function keep nothing of it past the call.

A reference to another crate’s value, such as ratatui’s &mut Frame, is lent to the function for the call instead. So is a slice of such values, such as &[Update]. Its methods reach the native value itself. The borrow ends when the call returns, as in Rust. A result may keep what the call was lent. In view<'a>(&'a self, inbox: &'a inbox::State, updates: &'a [Update]) -> Element<'a, Message>, the element that inbox::view(inbox, updates) gives borrows both for as long as native code holds the result. So does an element that a native part of self gives, such as self.wizard’s. Apps and libraries shows one.

Native trait objects

A marked function takes, keeps and returns a native trait’s objects. Native code calls their methods. A marked type that implements a native trait becomes its object too. With impl page::Page for BadgePage in a marked module, Box::new(BadgePage { .. }) gives a Box<dyn page::Page> that native code keeps. Its &self and &mut self methods run the marked impl on the value the box holds. So a change that update makes is there at the next call. A save that changes a method’s body takes effect at its next call.

A marked value lent as a &dyn page::Page is the same value that marked code keeps. Marked code writes it as &page as &dyn page::Page, or as &page where a function takes one. An Rc<dyn page::Page> or Arc<dyn page::Page> of one crosses too, as Rc::new(page) as Rc<dyn page::Page>.

A &self method may call back into the same object through native code. For example, a native helper may call title() while summary(&self) runs. Every &self call shares the one value, as a shared borrow does.

A trait with supertraits, such as pub trait Page: Debug + PageClone, works when the marked type implements them. The object’s Debug, Display, Clone, PartialEq, Eq, Default, PartialOrd and Ord run the marked type’s own impl. That impl may be derived or written. Its Hash runs a derived impl. A supertrait that is another of your crate’s traits runs its marked impl. A supertrait the marked type lacks is rustc’s E0277, as under cargo check.

Marked code calls a native trait’s &self methods on an object it holds, as it calls a crate trait’s. Imports says which methods qualify.

A method may return a reference to a native value, as Rust does. fn meta(&self) -> &'static Meta { &META } and fn blocks(&self) -> &'static [Block] { BLOCKS } give native code the static itself. fn state(&self) -> &State { &self.state } lends the field where the value holds it, for as long as native code borrows the object.

&'static slices and text constants

A marked module builds a native module’s structs and enums from literals, as in Rust. A field of type &'static str takes a string literal. A field of type Option<&'static str> takes Some("…") or None. A field of type &'static [Block] takes a slice literal &[…].

A public static or const of a marked module, such as pub static BLOCKS: &[page::Block] = &[…];, is compiled into rawr’s copy of the crate as written. So native code reads badge::BLOCKS as a Rust item. Marked code reads such a static where native code holds it and copies none of it. BLOCKS.len(), BLOCKS[i] and for block in BLOCKS read native code’s blocks. So does a match on each one. A group’s children are read the same way. &BLOCKS[1..2] lends a range of the blocks to a native function.

A native function that keeps its blocks, such as State::new(page_index, blocks: &'static [Block]), takes BLOCKS or a range of it as the static itself. It takes a slice literal &[Block::Md("…")] as Rust promotes it. That literal lives for as long as the program runs. A const is built again at each read, as Rust inlines it. An edit to such a static is a native change. rawr builds the native code again and restarts the program.

A marked module reads a native crate’s const or static of &str, such as pub const UI_FAMILY: &str = "Inter Tight";, as &'static str. It passes fonts::UI_FAMILY to a native function that takes &'static str, such as Font::new, as in Rust. rawr makes its string at the first read and gives that same string at each read after. So a call that keeps it holds one string for as long as the program runs.

A const or static of a slice of numbers, bool or char, such as pub const BYTES: &[u8], reads as a slice of rawr’s copy of its elements. BYTES.len() reads it. for byte in BYTES gives &u8.

Statics in a function body

A static declared inside a marked function’s body is named only in its block, as in Rust. One of a native type is a native value that lives as long as the program. rawr makes it the first time its block runs. Its address never changes, so native code may keep a &'static of it, as tracing’s registry keeps each callsite. A method that takes &'static self and a function that takes a &'static of a native type take such a static. A crate’s macro that declares statics gives each call statics of its own. A body’s static of another type is built again at each read, as a const is.

A static’s initializer may name a static of its block written before it, as static SITE: Callsite = Callsite::new(&META); after static META: Metadata = Metadata::named("site"); does. Statics may also refer to each other, as tracing’s META and __CALLSITE do. static SITE: Callsite = Callsite::new(&META); before static META: Metadata = Metadata::new("site", &SITE); works. Each then points at the other.

A save that leaves the statics’ declarations as they were keeps the statics and their values. A save that changes a declaration, or moves it to another line, makes new statics. The program keeps running.

Generic functions

Native code may call a marked function that is generic over a type, as a widget module generic over its Message is. Take pub fn row_group<'a, Message: Clone + 'a>(label: &'a str, message: Message) -> Element<'a, Message> in a marked widget/sidebar.rs. Native code calls it at each of its message types. It may call it directly or from a generic function of its own, such as fn small_row<'a, M: Clone + 'a>(..).

rawr learns which types native code uses from rustc’s check of your crate. It compiles the marked function once for each of those types. A save that changes the function’s body swaps in, as for any marked function. Native code that calls it at a new type is a native change, so rawr builds the native code again.

The methods of a generic marked type work the same way, as the builder methods of a Sidebar<'a, Message> do. So does a generic function that also takes an impl Trait argument.
