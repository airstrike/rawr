iced

A marked file uses iced’s own API through bindings that rawr-import generates. This page says how, and where the gaps are.

iced’s own API

The iced a marked file calls is the iced in your Cargo.toml. rawr-import reads its public API and generates the bindings your marked files call, as it does for any crate. Nothing in rawr is written by hand for iced.

  • Widgets, Element, Task and Subscription are iced’s own types. Their methods are iced’s own.
  • Your State and Message cross into iced as Rust types the runner makes for them. Generic items and your own types says how.
  • Values cross both ways between native code and a marked function. A marked function takes native values by value or lent as & or &mut, and a change it makes through &mut reaches the caller. It can give back a native type, such as a native Message or an iced::Element<'a, Message>, bare or inside an Option, a Vec, a tuple or a Result.
  • A function written -> impl Widget<Message> works, and so does a widget that iced’s own functions wrap and hold past the call, as the modal, pane_grid and loupe examples do.
  • A project has one iced, the one Cargo builds in the project’s target/. rawr run and cargo build share it. Nothing of iced is prebuilt or written into rawr.
  • iced’s macros, such as column! and row!, are iced’s own. Macros describes how rawr expands a crate’s macros.
  • An item the bindings don’t reach yet fails with an error.

Rust crates in an iced app

An iced app uses its other dependencies as Imports describes.

Cargo.toml
[dependencies]
mathx = { path = "mathx" }
iced = { git = "https://github.com/iced-rs/iced", rev = "be88873d38544455e26c7a104eb757da2cbbac6b" }

A custom iced widget written in Rust is imported like any other item. A Message can hold an imported value, and a match can bind it.

Diagnostics

rawr check checks an app without opening a window. Errors look like rustc’s. Delete the Decrement arm from the counter and it reports the missing arm:

rawr checkexit 1
error[RAWR-RESOLVE-MATCH]: invalid match for `Message`: non-exhaustive patterns; missing Message::Decrement
 --> src/main.rs:22:9-26:9
 22 |         match message {
    |         ^^^^^^^^^^^^^^^
    | ...
 26 |         }
    | ^^^^^^^^

Most errors rustc would give have rustc’s code and wording, such as error[E0308]: mismatched types. One rustc gives without a code, as a syntax error or cannot find macro, prints a plain error:. An error rustc has no counterpart for keeps a RAWR- code, which names the stage that failed. So does the missing arm above, where rustc gives E0004. Those codes will change while rawr is pre-alpha.

iced’s own examples

iced’s examples run as the generated bindings reach the items they use. iced names the ones known to run unchanged but for the // rawr line.

The ?play bot, and the playground’s Run on server, answer an iced program with what it printed and a picture of its window at the program’s own scale_factor. A program that settles once it has booted and its tasks have finished gets a PNG of that frame. A program that keeps changing on its own gets a GIF that plays once and holds its last frame. It has no window to click. The playground in the browser doesn’t run iced programs yet.
