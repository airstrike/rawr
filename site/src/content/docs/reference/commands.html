Commands

Every command you type as rawr .., and the extensions it hands programs to.

Paths

Most commands take an optional path. The path can be a crate directory, its Cargo.toml or a single .rs file. Without a path, rawr looks in the current directory and its parents for a crate with a marked file. The crate root is the binary cargo run runs, else the library, as cargo metadata lists them. That binary is the package’s only one or the one default-run names. A package with several binaries and no default-run stops with the list of its binaries, as cargo run does. The root or a module it declares must start with // rawr.

--bin <name> picks a binary of the package, as under cargo run --bin. -p <name> picks a package of the workspace. run, check and test take both.

--features <list> (or -F), --no-default-features and --all-features choose the package’s features, as under cargo run. run, check and test take them, and rawr hands them to Cargo as written. See Features.

A .rs file that a package lists as a binary runs as that package’s binary, with its dependencies and profile. Any other single file runs on its own, with or without the marker. rawr runs its top-level statements and then calls fn main.

Commands of rawr

These come with rawr-cli, which needs Rust 1.95 or newer. rawr-cli also installs cargo-rawr, so cargo rawr run works the same as rawr run.

CommandWhat it does
rawr [run] [path]Checks a program and runs it. run is the default command, so rawr alone runs the crate in the current directory. Errors from cargo check are printed after a program that runs once. A program with Rust dependencies or native modules goes to rawr-import. An iced app goes there too, as Apps and libraries describes.
rawr check [path]Checks a program without running it. It prints Checked and the entry path, or the first error. Then it runs cargo check and prints cargo check passed or rustc’s errors. It exits with status 1 if either check fails.
rawr test [path] [filter] [-- options]Runs the program’s #[test] functions, as cargo test runs them. Tests says more.
rawr new <path>Creates a Cargo crate with no dependencies. Its src/main.rs starts with // rawr and prints three lines. It refuses a path that holds files.
rawr new <path> --template <name>Creates a crate from a template that an installed extension offers. rawr new --help lists the templates. No extension offers one today.
rawr mcp [path]Runs an MCP server on stdio for coding agents such as Claude Code and Codex. Relative paths in its calls start at path, else the current directory. Installed extensions add tools to it. Agents describes it.
rawr init [--claude] [--codex] [path]Registers rawr mcp in the project’s agent config: .mcp.json for Claude Code and .codex/config.toml for Codex. Without a flag it looks for a .claude or .codex directory. It keeps the old file as .bak.
rawr doctor [path]Shows where rawr and each extension are and the program it finds. An extension that isn’t installed is shown with the commands that install it. Then it shows each installed extension’s own report, if it has one.
rawr -h, --helpPrints the help. For each installed extension it shows where it was found, which programs it serves and which commands it adds.
rawr -V, --versionPrints the version.

Set RAWR_VERBOSE=1 to see how a program was loaded and which binary ran it.

Tests

rawr test builds the program as cargo test builds it, so #[cfg(test)] items are in and cfg!(test) is true. Then it runs each #[test] function of the crate one after another, in name order. It reports them in cargo test’s format: running N tests, a test name ... ok or FAILED line for each, the output and panic of each failure, and the test result: line.

  • A test passes when it returns. A test that returns Err fails with Error: and the error.
  • #[should_panic] passes when the test panics. #[should_panic(expected = "text")] also needs text in the panic’s message.
  • #[ignore] and #[ignore = "reason"] leave a test out. It is reported as ignored.
  • What a test prints is shown only when it fails, as cargo test shows it.

The first argument that isn’t a path filters the tests by name, as cargo test add does. Options after -- are libtest’s: more name filters, --exact, --skip <filter>, --ignored, --include-ignored and --nocapture. --test-threads is accepted, and tests always run one at a time. rawr test -p <package> tests a package of the workspace.

A program that isn’t built for its tests still has its #[cfg(test)] items parsed, as rustc parses them. A syntax error in a test module stops rawr run and rawr check too.

Commands from extensions

rawr runs run, check, test, new, doctor, mcp and init itself. It hands other commands to the installed extension that adds them. It looks for rawr-<name> binaries next to its own binary first and then on PATH.

  • rawr-import runs rawr run and rawr check for programs with Cargo dependencies or native modules. It adds rawr cache clean, which removes what rawr’s home holds that no build has used lately: hosts, rawr’s runtimes, shared bindings and the nightly’s check build. It skips anything a running build holds and never waits for one.

rawr preview and rawr snapshot came with rawr-iced, which is gone. rawr preview comes back as open work. Editor previews says more.

Exit status

  • 0 when the command succeeds.
  • 1 when a check fails or when main returns Err. rawr check also exits with status 1 when cargo check fails.
  • 101 when a program panics, or when a test of rawr test fails.
  • 134 when a program panics under a profile with panic = "abort", as for Cargo’s build.

Files rawr writes

  • target/<host>/debug/ holds the compiled crates. rawr run and cargo build share them.
  • target/rawr/ holds rawr’s cached data and the generated runner. cargo clean removes it. Projects that share one target directory, through CARGO_TARGET_DIR, share its cache. When rawr starts a check or run there, it removes what the other projects left, unless one of them is being checked or run at that moment.
  • rawr’s home, ~/.cargo/rawr unless RAWR_HOME says otherwise, holds what every project on the machine shares: rawr’s runtime, the bindings and the nightly’s check build. rawr cache clean removes what no build has used lately. It never removes what a running build is using.
  • rawr compiles one runtime for each rawr version and toolchain, in runtime/ in rawr’s home. When it compiles a new one, it removes each runtime that no installed rawr uses and no build used in the last hour. A rawr that was reinstalled or deleted no longer counts as installed.
