Play sandbox

How the playground and the ?play bot run a snippet. The bot runs it on its server. The playground runs it in your browser. Both run plain Rust programs with the same limits.

The sandbox

A snippet has no files, no environment variables, no process and no network. rawr’s engine starts with none of them, and ?play grants none (see Access). A call that needs one fails at the call, as the operating system would refuse it. On the bot’s server each run is also its own process, and that process starts with an empty environment.

The grant covers the snippet’s own code. A crate the snippet uses, such as iced or tokio, runs as native code and calls the operating system directly. So the bot approves no crate or feature whose code reads files, opens sockets, spawns processes or reads the environment for the snippet. The bot’s container bounds what the rest can reach.

The clock

A program reads the real clock. Real time counts against the time budget. In the browser, Instant reads the page’s performance.now() and SystemTime reads the page’s time.

Output

The reply is the program’s stdout and stderr in the order it wrote them. Stderr shows in its own colour in the playground. The reply shows the exit status when it isn’t 0.

Where ?play differs from rawr run

A snippet has no files and no window. It has no Cargo.toml, but it can declare its dependencies in a frontmatter block.

Crates

A snippet with no frontmatter can use iced, iced_test, tokio and ratatui. It runs on the playground’s prebuilt runner, whose bindings are built once with the bot. It can make the calls into those crates that the runner’s program makes (play/universe), at the types that program makes them. Those are tokio’s spawn, sleep and spawn_blocking, and iced’s calls in these examples:

  • the counter: column! and row! with spacing, padding and alignment, button, and text of an i64, a &str or a String such as format! makes;
  • a slider of an f32, and one of Radians over Radians::RANGE;
  • a pick_list of the snippet’s own enum, with on_select and placeholder;
  • a subscription of window::frames(), of time::every ticks of a Duration, of keys matched from keyboard::listen(), or several through Subscription::batch;
  • iced::run, and iced::application with a subscription, a scale_factor, or both in either order.

ratatui’s calls are those of the landing page’s terminal snippet (play/universe/programs/ui.rs). It splits a Rect with Layout::vertical and Constraints, renders a Paragraph in a Block::bordered() with a title into a Buffer, and reads each cell’s symbol().

The prebuilt runner also holds whole programs, and a snippet can make the calls any one of them makes. They are iced’s own examples that run under rawr run and need no files, no network and no other crate, listed in play/universe/examples.txt: arc, counter, pick_list and styling. With them is iced’s solar_system drawn with plain shapes instead of images, and a greeting whose text_input takes typed text through on_input and on_submit. In ?play, which has no keyboard, a snippet types into one with iced_test’s simulator: click of its id, typewrite, tap_key, into_messages and find. Together they add a canvas of a Program, its Cache and Frame with fills, strokes, a LineDash, rotations and translations, iced::application::timed, .theme(..) of a theme or of a function, and styling’s checkbox, toggler, progress_bar, scrollable, container, rule, center and text_input.

The snippet’s types take the places of the types of the program whose calls it makes, in the order it defines them, whatever their names. For the program above, its first three are the state, the message and the enum. The functions a call takes, such as an application’s view or a slider’s message, may have any names. Each call of that program takes one function at each place, so a snippet that passes two different functions to calls of one kind, such as two f32 sliders with two messages, doesn’t compile there.

Another call doesn’t compile there either, and the error points at it:

error: this use of a crate is not available in this prebuilt runner
  --> play.rs:12:17
   |
12 |         column![text(self.volume as f64), button("Up").on_press(Message::Up)]
   |                 ^^^^^^^^^^^^^^^^^^^^^^^ the runner was not built with this call

A crate item that program doesn’t use at all gets rustc’s error for a missing item, such as error[E0425]: cannot find function `radio` in module `iced::widget`.

An iced program answers with what it printed and a picture of its window, drawn at the program’s own scale_factor. The picture is a PNG of the window once the program has booted and the tasks it started have finished. When the program keeps changing on its own, through a subscription or a widget’s animation, the picture is a GIF of each change instead. It shows 20 frames a second, for at most 100 frames and within the snippet’s time, and plays once and holds the last frame. It plays at the program’s pace, however long the bot takes to draw each frame: a change made on a frame shows for one frame’s 50 ms, and a change made on the program’s own clock, such as a time::every tick, shows for the time that clock ran. A program that reads Instant::now() on each frame still sees the bot’s time, so its animation can move faster in the GIF than on a fast machine.

A snippet that needs another call to these crates, or another crate, can name its dependencies in a frontmatter block. The bot then builds a runner for the calls that snippet makes.

Dependencies

A snippet that starts with a cargo-script frontmatter block runs on the bot as rawr run play.rs runs a script. The bot expands the frontmatter as cargo does. It builds the dependencies, and the bindings for the calls the snippet makes. The snippet then runs on the runner built for it, with the sandbox and the limits of any other snippet.

---
[dependencies]
ratatui = { version = "0.30", default-features = false }
---
use ratatui::layout::Rect;

fn main() {
    println!("{}", Rect::new(0, 0, 20, 4).area());
}

Every dependency must be one of the bot’s approved crates, which play/approved/Cargo.toml lists. A snippet names one by a version that its locked version meets, or by the same git repository at the same rev.

A snippet may ask for any of a crate’s approved features. The bot builds the crate with all of them, as its image built it, so the build reuses what the image compiled. tokio’s fs, net, process and signal, ratatui’s terminal backends, and iced’s image and svg are not approved. A snippet that asks for them, directly or through its own [features], is refused. So is one that turns ratatui’s default features on.

The bot refuses a snippet that names any other crate, or an approved one at another version or from another source. It refuses it before it builds anything. The reply is one line that lists the approved crates, or a crate’s approved features. A frontmatter may hold [package], [features], [lints] and dependency tables. The bot refuses a table that changes how it builds, such as [profile] or [patch].

The bot builds offline. Its image holds a copy of each approved crate and of everything they depend on. A snippet’s build reads only that copy, so it downloads nothing and runs no build script but the approved crates’ own.

Every snippet builds in one build directory on the bot. The bot’s image builds each set of approved crates once, with their approved features, and a snippet’s build reuses that.

An error in the frontmatter, or in a dependency’s build, is cargo’s or rustc’s own message, and it names the snippet play.rs. A frontmatter that declares no dependency runs as the same snippet without the block.

The playground runs a frontmatter snippet in the browser when each dependency it names is a crate of the browser’s prebuilt runner. The browser builds nothing, so any other dependency gets one line that says so.

The prebuilt runner in the browser

The prebuilt runner also runs in the browser, built for wasm32 with the same program, so a snippet makes the same calls there. The playground and an iced snippet’s Run on this site use it. Its window is drawn in the page, in place of the snippet’s output, and its buttons answer clicks there with no round trip to a server. Before Run, the output is the picture the bot drew. Each Run gets a fresh copy of the runner, compiled once for the page, because a page runs one event loop per copy. An edit reloads the program in its copy, with its state kept, and gets a fresh copy only when it can’t reload there or the program has ended.

The runner is a WebAssembly module of about 53 MB. The site sends it brotli-compressed, at about 5 MB, and the browser decompresses it as it downloads. A page downloads it once, at its first Run that uses it.

iced draws with WebGPU where the browser has it, and with WebGL2 elsewhere. On Safari and on every browser on iOS it draws with WebGL2, because WebKit’s WebGPU fails the way iced uploads its shapes and text.

A snippet’s keys reach its window only while that window has focus. A click or Tab gives it focus, and the window shows an outline while it has it.

An async main

A main that is async needs a runtime’s attribute, such as #[tokio::main], as in Rust. Without one the snippet doesn’t compile, with rustc’s error.

error[E0752]: `main` function is not allowed to be `async`

A note is a short line that comes with the reply.
