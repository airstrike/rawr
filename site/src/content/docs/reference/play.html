Play

How the playground and the ?play bot run a snippet. Both run plain Rust programs with the same limits.

The sandbox

A snippet has no files, no environment variables, no process and no network. rawr’s engine starts with none of them, and ?play grants none (see Access). A call that needs one fails at the call, as the operating system would refuse it. On the server each run is also its own process, and that process starts with an empty environment.

The grant covers the snippet’s own code. A crate the bot’s universe binds, such as iced or tokio, runs as native code and calls the operating system directly. The server’s container bounds what that code can reach.

The clock

A program reads the real clock. Real time counts against the time budget.

Output

The reply is the program’s stdout and stderr in the order it wrote them. Stderr shows in its own colour in the playground. The reply shows the exit status when it isn’t 0.

A run over the Discord rate limit gets an hourglass reaction instead of a reply. An edit over the limit is ignored.

Where ?play differs from rawr run

A snippet has no Cargo.toml, no files and no window.

Crates

In ?play a snippet can use iced, iced_test and tokio, through bindings built once with the bot. It can make the calls into them that the bot’s universe program makes (play/universe), at the types that program makes them. Those are tokio’s spawn, sleep and spawn_blocking, and iced’s calls in these examples:

  • the counter: column! and row! with spacing, padding and alignment, button, and text of an i64, a &str or a String such as format! makes;
  • a slider of an f32, and one of Radians over Radians::RANGE;
  • a pick_list of the snippet’s own enum, with on_select and placeholder;
  • a subscription of window::frames(), of time::every ticks of a Duration, of keys matched from keyboard::listen(), or several through Subscription::batch;
  • iced::run, and iced::application with a subscription, a scale_factor, or both in either order.

The universe also holds whole programs, and a snippet can make the calls any one of them makes. They are iced’s own examples that run under rawr run and need no files, no network and no other crate, listed in play/universe/examples.txt: arc, counter, pick_list, progress_bar and tooltip. With them is iced’s solar_system drawn with plain shapes instead of images. Together they add a canvas of a Program, its Cache and Frame with fills, strokes, a LineDash, rotations and translations, iced::application::timed, and .theme(..) of a theme or of a function.

The snippet’s types take the places of the types of the program whose calls it makes, in the order it defines them, whatever their names. For the program above, its first three are the state, the message and the enum. The functions a call takes, such as an application’s view or a slider’s message, may have any names. Each call of that program takes one function at each place, so a snippet that passes two different functions to calls of one kind, such as two f32 sliders with two messages, doesn’t compile there.

Another call doesn’t compile there either, and the error points at it:

error[RAWR-RESOLVE-HOST-OPERATION]: this use of a crate isn’t among the universe’s bindings
 --> play.rs:12:17-12:40
 12 |         column![text(self.volume as f64), button("Up").on_press(Message::Up)]
    |                 ^^^^^^^^^^^^^^^^^^^^^^^ the universe’s program doesn’t make it

A crate item that program doesn’t use at all gets rustc’s error for a missing item, such as error[E0425]: cannot find function `toggler` in module `iced::widget`.

An iced program answers with what it printed and a picture of its window, drawn at the program’s own scale_factor. The picture is a PNG of the window once the program has booted and the tasks it started have finished. When the program keeps changing on its own, through a subscription or a widget’s animation, the picture is a GIF of each change instead. It shows 20 frames a second, for at most 100 frames and within the snippet’s time, and plays once and holds the last frame. It plays at the program’s pace, however long the bot takes to draw each frame: a change made on a frame shows for one frame’s 50 ms, and a change made on the program’s own clock, such as a time::every tick, shows for the time that clock ran. A program that reads Instant::now() on each frame still sees the bot’s time, so its animation can move faster in the GIF than on a fast machine. Use rawr run for a program that needs another crate or call. The playground in the browser uses rawr’s std and no crates.

An async main

A main that is async needs a runtime’s attribute, such as #[tokio::main], as in Rust. Without one the snippet doesn’t compile, with rustc’s error.

error[E0752]: `main` function is not allowed to be `async`

Notes and replies

A note is a short line that comes with the reply.

Notes on program output
