Overview

rawr checks a program before it runs it. This reference lists the Rust that passes that check.

At a glance

Code that rawr doesn’t support fails the check with an error that names the construct. These are the largest gaps:

  • macro_rules! isn’t supported. Only the built-in macros work.
  • i128, u128 and returning &mut from a function aren’t supported.
  • async code runs in iced apps, in a ?play program whose main is async, and in a crate whose main is #[tokio::main] async fn main or another runtime’s.
  • Only part of std works. std lists it.
  • Borrow checking is partial. rawr rejects a use after a move and two live &mut borrows of one value. It accepts some code rustc rejects, so rawr check also runs cargo check.

How a program runs

rawr checks a whole program before any of it runs. The check resolves names, types, traits and method calls. It also checks that every match covers every case. A program that fails the check doesn’t start.

A program is a Cargo crate or a single .rs file. Run says which files are interpreted.

A single file can hold items, top-level statements, or both. Top-level statements run first, as the body of a fn main would, and then rawr calls fn main if there is one. A function can’t read their variables. Cargo doesn’t build a file with top-level statements, so keep them to snippets and the playground.

parse.rs
fn parse(s: &str) -> Result<i64, String> {
    s.parse::<i64>().map_err(|e| format!("{s:?}: {e}"))
}

fn main() -> Result<(), String> {
    let n = parse("42")?;
    println!("n = {n}");
    let m = parse("forty")?;
    println!("m = {m}");
    Ok(())
}
rawr run parse.rsn = 42 Error: "\"forty\": invalid digit found in string" exit status 1

A program prints what the Rust binary prints and exits with the same status. An error from main exits with status 1. A panic exits with status 101.

Not supported yet

These are valid Rust that rawr rejects today. Each one fails the check with an error that names the construct. rawr reports one error per check.

Syntax and items

  • A glob import of an enum’s variants, as in use Shape::*;.
  • const fn.
  • char ranges such as 'a'..='e'.
  • macro_rules!.
  • serde’s #[derive(Serialize, Deserialize)] on your own types.
  • async and .await outside iced, except an async fn main in ?play or under a runtime’s attribute in a crate.
  • try_join! and select! outside iced and ?play.
  • A const captured in a format string, as in "{LIMIT}". Pass it as an argument instead.

Types and borrowing

  • i128 and u128.
  • Returning &mut from a function or method.
  • Two mutable borrows of fields of one struct at once, as in swap(&mut p.x, &mut p.y).
  • &dyn Trait arguments such as &dyn Debug. Box<dyn Trait> works.
  • Comparing with < a None whose type isn’t known yet.
  • impl Drop.

Standard library

  • Cell, Weak and Mutex.
  • std::fs, and std::io beyond Error and ErrorKind.
  • VecDeque and BinaryHeap.
  • std::process::exit and Box<dyn std::error::Error>.
  • write! into a String through std::fmt::Write.
  • Formatter::pad.
  • f64::NAN, f64::INFINITY and f64::EPSILON.
  • char::from(u8) and char::from_u32. byte as char works.
  • Vec::binary_search.
  • dbg!, line!, file!, column! and module_path!.

Differences from cargo run

A program that passes both rawr check and rustc prints the same output, except in these known cases. Each one is a defect to fix.

  • HashMap order. rawr iterates a HashMap in key order. Rust’s order is random.
  • Width on your own Display. rawr pads a user Display impl’s output to the width in {:>6}. Rust ignores the width unless the impl calls f.pad.
  • Panic messages. rawr writes a panic’s message as a diagnostic with the source span. Rust writes thread 'main' panicked at ...
  • A large u64 in generic code. Inside a generic function, adding or multiplying u64 or usize values through T: Add panics once the result passes i64::MAX. Rust gives the result.

Code that rawr refuses rather than run differently

  • A tokio::select! branch with an if condition. Check the condition before the select!, or in the branch’s body.

Code that rawr accepts and rustc rejects

Some code passes rawr’s own check and fails cargo build. rawr check runs cargo check too, which reports these. Commands describes its output.

  • There is no borrow checker beyond the two rules above. A shared borrow held across a mutation is accepted. So is returning a reference to a local.
  • String and &str are one type to the checker. Passing "x" where a String is expected is accepted.
  • Lifetimes are not checked. fn f(a: &str, b: &str) -> &str is accepted.
  • An array reference is accepted where &Vec<T> is expected.
  • Private struct fields can be read and set from another module. Private functions are rejected, as in rustc.
  • HashMap can be used without a use line.
  • Out-of-range literals such as let x: u8 = 300 are accepted.
  • Send and Sync bounds are not checked. An Rc passes T: Send.
  • Top-level statements are accepted.
  • In iced code, a concrete widget is accepted where an Element is expected.
  • .await on an iced Task is accepted.
  • Returning a field of &self by value, as in fn name(&self) -> String { self.name }, is accepted. rustc reports E0507.
