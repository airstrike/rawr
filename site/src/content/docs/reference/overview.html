Overview

rawr checks a program before it runs it. This reference lists the Rust that passes that check.

At a glance

Code that rawr doesn’t support fails the check with an error that names the construct. These are the largest gaps:

  • macro_rules! isn’t supported. Only the built-in macros work.
  • async code runs in iced apps, in a ?play program whose main is async, and in a crate whose main is #[tokio::main] async fn main or another runtime’s.
  • Only part of std works. std lists it.
  • Borrow checking covers the borrows of a function’s locals, ended where rustc ends them, including those a call’s result keeps, those a struct, a collection or an Option holds, and those a closure captures. It covers temporaries and what a function returns against its signature too. A few borrows aren’t checked yet, so rawr check also runs cargo check. How it works explains the check.

How a program runs

rawr checks a whole program before any of it runs. The check resolves names, types, traits and method calls. It also checks that every match covers every case. A program that fails the check doesn’t start.

A program is a Cargo crate or a single .rs file. Run says which files are interpreted.

A single file can hold items, top-level statements, or both. Top-level statements run first, as the body of a fn main would, and then rawr calls fn main if there is one. A function can’t read their variables. Cargo doesn’t build a file with top-level statements, so keep them to snippets and the playground.

parse.rs
fn parse(s: &str) -> Result<i64, String> {
    s.parse::<i64>().map_err(|e| format!("{s:?}: {e}"))
}

fn main() -> Result<(), String> {
    let n = parse("42")?;
    println!("n = {n}");
    let m = parse("forty")?;
    println!("m = {m}");
    Ok(())
}
rawr run parse.rsn = 42 Error: "\"forty\": invalid digit found in string" exit status 1

A program prints what the Rust binary prints and exits with the same status. An error from main exits with status 1. A panic exits with status 101. It prints what a program built by Cargo prints on stderr:

thread 'main' panicked at src/main.rs:5:5:
boom 3
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace

The path is the file’s path from the workspace root, as Cargo gives it. In ?play and in the browser the file is play.rs.

Supported Rust

Each page lists one area of the language, with an example for each construct.

ItemsFunctions, structs, enums, traits, modules and use. TypesNumbers, strings, collections, smart pointers and casts. GenericsBounds, trait objects and operator traits. Patternsmatch, if let, let else and loops. MovesMoves, partial moves, drops and clones. ClosuresCaptures, Fn traits and async code. MacrosThe built-in macros and format strings. stdThe parts of the standard library that work.

Not supported yet

These are valid Rust that rawr rejects today. Each one fails the check with an error that names the construct. rawr reports one error per check.

Syntax and items

  • A static mut.
  • macro_rules!.
  • serde’s #[derive(Serialize, Deserialize)] on your own types.
  • async and .await outside iced, except an async fn main in ?play or under a runtime’s attribute in a crate.
  • try_join! and select! outside iced and ?play.
  • A const captured in a format string, as in "{LIMIT}". Pass it as an argument instead.

Types and borrowing

  • A range of floats that excludes its end, as in 0.5..1.0. 0.5..=1.0 works.
  • Returning a &mut to a map’s entry, as in self.counts.entry(k).or_insert(0).
  • Returning a &mut borrowed from a parameter other than &mut self or a free function’s first &mut parameter.
  • Giving a new borrow to a &mut local that borrows a field or an element, as in let mut r = &mut s.left; r = &mut s.right;. A &mut local of a whole local can be given new borrows, as in r = &mut b; or prev = r;, except in an async body.
  • A &mut chosen by a branch, as in r = if c { &mut a } else { &mut b };. Assign it in each branch instead.
  • An output that holds &mut other than &mut T and Option<&mut T>, as in Vec<&mut T>.
  • &dyn Trait arguments such as &dyn Debug. Box<dyn Trait> works.
  • Comparing with < a None whose type isn’t known yet.
  • A value whose type implements Drop inside an Rc, Arc, RefCell, map or set, or taken by a move closure. See Drop.

Standard library

  • Weak and Mutex.
  • Cloning a struct, enum or Vec that holds a Cell or RefCell outside an Rc.
  • Rc::strong_count, Rc::weak_count and Rc::ptr_eq, and the same for Arc. An Rc is its value in rawr, so it has no count.
  • std::fs, and std::io beyond Error and ErrorKind.
  • BinaryHeap.
  • std::process::exit.
  • Formatter::pad.
  • char::from(u8) and char::from_u32. byte as char works.
  • Vec::binary_search.

Differences from cargo run

A program that passes both rawr check and rustc prints the same output, except in these known cases. Each one is a defect to fix.

  • HashMap order. rawr iterates a HashMap in key order. Rust’s order is random.
  • Width on your own Display. rawr pads a user Display impl’s output to the width in {:>6}. Rust ignores the width unless the impl calls f.pad.
  • The column of an index panic. rawr places a panic from indexing at the [, as Rust does for a Vec. For an array or a slice Rust places it at the start of the expression.
  • Drops in a panic. rawr stops at a panic without running drop. Rust runs it for each value the panic unwinds past.
  • A large integer in generic code. Inside a generic function, adding or multiplying u64 or usize values through T: Add panics once the result passes i64::MAX. With i128 or u128 values it panics when both values fit an i64 and the result doesn’t. Rust gives the result.
  • Arithmetic on literals alone. An operation whose operands are all unsuffixed literals is computed as an i64. So let x: i128 = 10_000_000_000 * 10_000_000_000; panics where Rust gives the result. A suffix, as in 10_000_000_000i128, gives Rust’s result.

Code that rawr refuses rather than run differently

  • A tokio::select! branch with an if condition. Check the condition before the select!, or in the branch’s body.
  • A let that binds a value borrowing a &mut buffer its imported call fills, as let event = reader.read_event_into(&mut buf)?;. rawr gives the buffer back when the value’s frame ends, which for a let is the end of its block, where Rust’s borrow ends at the value’s last use. Match on the call in a statement of its own. Values that borrow explains frames.
  • A call or assignment written before a call whose value borrows, in the same statement, as let n = note(&text) + Parser::new(&text).count();. rawr opens the borrowing call’s frame ahead of its statement, so the earlier call would run after it. The error names the statement’s line. Give the earlier call a statement of its own. A call after the borrowing one, or an earlier operand that isn’t a call, is fine.
  • capacity() of a Vec in a field, in an element or behind a reference. It works on a local or a temporary Vec. It is also refused for a Vec of u8, i8, bool or (), whose growth rawr doesn’t follow.

Code that rawr accepts and rustc rejects

Some code passes rawr’s own check and fails cargo build. rawr check runs cargo check too, which reports these. Commands describes its output.

  • A borrow kept by a closure that takes and returns borrows isn’t checked, as |a: &u32| &x passed where impl Fn(&u32) -> &u32 is expected. Nor is one an async block captures, or one a closure stores in what it captured.
  • A borrow kept by an item that a method gives from a container isn’t checked: copied, cloned, collect, next and the like, and an Option’s or Result’s map. Nor is one held by a value whose type has a Drop impl, or by a type with an impl written for its 'static instance.
  • A slice pattern’s rest @ .. binding and the bindings of a pattern on an imported value aren’t checked.
  • A returned borrow of a parameter whose type has several lifetimes isn’t checked against the output’s lifetime. An example is &self of a struct that has a lifetime parameter. A lifetime written in a type inside a body, as in let x: &'static i32 = &n;, isn’t checked.
  • A block’s value that borrows a temporary of its tail, as in let r = { String::from("a").as_str() };, isn’t checked.
  • A struct’s field whose type leaves out a struct’s lifetime, as w: Wrapper of struct Wrapper<'a>, is accepted. rustc refuses it with E0106. A field written as a reference without a lifetime is refused, as in rustc.
  • String and &str are one type to the checker. Passing "x" where a String is expected is accepted.
  • An array reference is accepted where &Vec<T> is expected.
  • Private struct fields can be read and set from another module. Private functions are rejected, as in rustc.
  • HashMap can be used without a use line.
  • Out-of-range literals such as let x: u8 = 300 are accepted.
  • Send and Sync bounds are not checked. An Rc passes T: Send.
  • VecDeque<T> and Vec<T> are one type to the checker. A Vec takes push_front, and a VecDeque takes sort.
  • A &str, a String or an error is accepted where a Box<dyn Error> is expected, without Box::new or .into().
  • Top-level statements are accepted.
  • In iced code, a concrete widget is accepted where an Element is expected.
  • .await on an iced Task is accepted.
  • Returning a field of &self by value, as in fn name(&self) -> String { self.name }, is accepted. rustc reports E0507.
  • A method of an imported impl that fixes its type’s arguments is accepted on every instance of the type. quick-xml’s read_event belongs to impl<'a> Reader<&'a [u8]>, and rawr accepts it on a Reader<String> too. Such a program stops with an error before the call runs, and cargo check reports rustc’s E0599.
  • into_owned() is accepted on any String, since rawr reads a crate’s Cow<str> as a String.
  • A value that borrows an imported call’s input, kept past the scope it was made in, is accepted by the check. Using it stops the program with an error that names rustc’s E0597, where rustc rejects the program.
