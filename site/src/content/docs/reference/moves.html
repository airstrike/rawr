Moves

A value that is not Copy moves when it is passed, assigned or stored by value, as in Rust. It drops with its last owner.

Use after a move

A use after a move fails the check, as rustc’s E0382 does. for x in v moves v. a + &b moves the String a. A method that takes its value, as o.unwrap() does, moves it. A value moved on one branch, or in a loop’s earlier iteration, is moved where the paths meet.

let a = String::from("ra");
let b = a + "wr";
println!("{a}"); // error: `a` was moved
rawr run use-after-move.rserror[E0382]: use of moved value: `a`

Run shows the check’s error. Write a.clone() + "wr" and the program prints ra.

Partial moves

Moving one field out of a struct leaves its other fields usable. So does moving a tuple’s member, as let b = t.1; does, or a field below a field, as let b = s.inner.b; does. Assigning the part again makes it usable. A let, if let or match pattern moves each part it binds by value, and a closure moves the parts its body moves out.

struct Person {
    name: String,
    city: String,
}

let p = Person { name: String::from("Ana"), city: String::from("Rio") };
let name = p.name;
println!("{}", p.city); // fine: only p.name moved

let pair = (String::from("a"), String::from("b"));
let (first, _) = pair;
println!("{}", pair.1); // fine: only pair.0 moved
rawr run partial-move.rsRio b

Drop

A type with impl Drop runs its drop where Rust drops the value. A local drops at the end of its block, in reverse order of declaration. drop(x) drops x at once. A value moved into a function drops at the end of that function. let _ = value; and a statement such as Noisy("t"); drop their value at the end of the statement. An assignment drops the value it replaces. return, break, continue and ? drop the locals of each block they leave. A moved value drops only with its new owner.

A struct’s fields drop after its own drop, in declaration order. The elements of a Vec, an array, a tuple, an Option, a Result and a Box drop in order too.

struct Noisy(&'static str);

impl Drop for Noisy {
    fn drop(&mut self) {
        println!("drop {}", self.0);
    }
}

let _a = Noisy("a");
{
    let _b = Noisy("b");
    println!("inner");
}
let c = Noisy("c");
drop(c);
let _ = Noisy("d");
let v = vec![Noisy("e"), Noisy("f")];
println!("end {}", v.len());
rawr run drop-order.rsinner drop b drop c drop d end 2 drop e drop f drop a

Some places cannot drop such a value where Rust does yet, and the check says so. They are an Rc, an Arc, a RefCell, a map or a set holding it, a move closure or async block that takes it, an async fn parameter, and an iterator over it. Vec methods that drop elements other than truncate and clear are refused too. A panic does not run drop.

Moving out of an index or a reference

Moving a value out of an index, or out of a field behind a reference or an Rc, fails the check as rustc’s E0507 does. Moving an element out of an array is E0508. Moving a field out of a type with impl Drop is E0509. Borrow it or clone it instead.

let v = vec![String::from("x")];
let s = v[0].clone(); // `let s = v[0];` is E0507
println!("{s}");
rawr run clone-out.rsx

Clones of Rc and Arc

A clone of an Rc or Arc is another handle to the same value. A change through a RefCell inside it shows through every clone.

use std::cell::RefCell;
use std::rc::Rc;

let log = Rc::new(RefCell::new(Vec::new()));
let writer = Rc::clone(&log);
writer.borrow_mut().push("saved");
println!("{:?}", log.borrow()); // ["saved"]
rawr run rc-refcell.rs["saved"]
