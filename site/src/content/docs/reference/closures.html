Closures

Closures capture their environment, as in Rust.

closures.rs
fn apply(f: impl Fn(i64) -> i64, x: i64) -> i64 {
    f(x)
}

fn scale(k: i64) -> impl Fn(i64) -> i64 {
    move |x| x * k
}

fn main() {
    let mut log = Vec::new();
    let mut add = |line: &str| log.push(line.to_string());
    add("first");
    add("second");
    println!("{:?}", log);
    println!("{} {}", apply(|x| x + 1, 1), scale(3)(2));
    let odd_squares: Vec<i64> = (1..=10).filter(|x| x % 2 == 1).map(|x| x * x).collect();
    println!("{:?}", odd_squares);
}

Captures

A closure that changes what it captures is FnMut. A move closure takes what it captures. It captures only the fields it uses, so move || s.a.len() moves s.a and leaves s.b usable. A closure that moves a captured value out, as || drop(s) does, can be called once.

A closure that doesn’t take what it captures borrows it, and keeps the borrow while the closure is used, as in Rust. It captures only the fields it uses. How it works explains the check.

A closure can use a &mut local, a function’s &mut parameter, a &mut pattern binding or a mutable loop’s element. It changes the place itself, so fn bump(r: &mut Vec<i32>) { let mut push = |x| r.push(x); push(1); } pushes onto the caller’s vector. Using the borrow while such a closure is live is rustc’s E0501. Making the closure while the borrow is borrowed elsewhere is E0500. Two such closures live at once are E0524.

A call can change one part of a local while a closure it runs uses another part. In pair.0.retain(|x| !pair.1.contains(x)), retain changes pair.0 and the closure reads pair.1, as Rust’s disjoint borrows allow.

let mut count = 0;
let mut tick = || count += 1;
tick();
tick();

let name = String::from("rawr");
let greet = move || format!("hi, {name}");
println!("{count} {}", greet());

Passing and returning closures

A function takes a closure as impl Fn(..) or as a generic F: Fn(..). It returns one as impl Fn(..) or Box<dyn Fn(..)>. A struct field can hold a Box<dyn Fn(..)>. A function can also take &mut impl FnMut(..). The closure passed can be a variable, as in twice(&mut add), or written in place, as in twice(&mut |x| v.push(x)). Each call changes what the closure captured where the caller has it.

struct Button {
    on_click: Box<dyn Fn() -> String>,
}

fn twice<F: Fn(i64) -> i64>(f: F, x: i64) -> i64 {
    f(f(x))
}

let b = Button { on_click: Box::new(|| String::from("clicked")) };
let four = twice(|x| x * 2, 1);
println!("{} {four}", (b.on_click)());
rawr run boxed-fn.rsclicked 4

Closures as values

A closure in a variable can be passed to a function, copied to another variable, or called from another closure. A closure that holds a value that is not Copy, or captures something by &mut, is not Copy, so let g = f; moves it. A use of f after that is rustc’s E0382. A copy of a Copy closure has its own copy of what it captured by value, as in Rust. After let mut d = c;, calling d doesn’t change what c sees. A parameter can be _ or another pattern.

let add = |(a, b): (i64, i64)| a + b;
let also_add = add;
let sums: Vec<i64> = vec![(1, 2), (3, 4)].into_iter().map(also_add).collect();
println!("{sums:?} {}", add((5, 6)));
rawr run copy-closure.rs[3, 7] 11

A path to a function is a value wherever Rust takes one, as an argument, a variable or a fn pointer. That includes a method, as in Counter::update, a &mut self method and a function with a &mut parameter among them. It also includes a trait’s method, as in Shape::area or <Square as Shape>::grow, and a generic method with its turbofish. A call through the path, as in Counter::update(&mut counter, message), changes counter as counter.update(message) does.

#[derive(Default, Debug)]
struct Counter { value: i64 }
impl Counter {
    fn update(&mut self, by: i64) { self.value += by; }
    fn view(&self) -> String { format!("value {}", self.value) }
}
fn run(update: impl Fn(&mut Counter, i64), view: impl Fn(&Counter) -> String) {
    let mut counter = Counter::default();
    update(&mut counter, 2);
    println!("{}", view(&counter));
}
fn main() {
    run(Counter::update, Counter::view);
}

Parameter types

A closure’s parameters take their types from where it is passed.

#[derive(Clone, Copy)]
struct Color {
    r: f32,
    g: f32,
}

fn shade(f: impl Fn(f32) -> Color) -> Color {
    f(0.5)
}

let base = Color { r: 0.0, g: 1.0 };
let c = shade(|r| Color { r, ..base });
println!("{} {}", c.r, c.g);

Async code

In an iced app, async fn, async blocks, async closures and .await work. iced describes how an app runs them. In ?play, a program whose main is async runs the same way. Play lists its tokio.

A crate whose main is #[tokio::main] async fn main, or another runtime’s main, runs on the runtime in its Cargo.toml. There, an async block or an async fn gives a Rust future, .await takes a future’s output, join! runs futures together, and tokio::spawn runs one of yours as a task. A closure you pass to spawn_blocking runs on a worker thread. Run describes how.

Other programs can’t use async yet.
