Imports

Use the crates in your Cargo.toml and your native modules from marked code. rawr-import compiles them with Cargo.

Install rawr-import

Once rawr-import is installed, rawr hands it every program with dependencies or native modules.

rawr-import needs 64-bit macOS or 64-bit Linux and the pinned Rust nightly nightly-2026-07-11 with the rustc-dev and rust-src components. It has been tested on Apple Silicon Macs. CI runs it on x86_64 Linux. Requirements lists the platforms.

rustup toolchain install nightly-2026-07-11 --component rustc-dev,rust-src
cargo +nightly-2026-07-11 install --locked --git https://github.com/airstrike/rawr rawr-import-cli
cargo +nightly-2026-07-11 install --locked --git https://github.com/airstrike/rawr rawr-import --features rustc-driver

rawr-iced imports an iced app’s dependencies the same way. It doesn’t need rawr-import installed.

Project setup

rawr-import builds your dependencies in the project’s target/ and shares them with cargo build. The project needs two files for that:

rust-toolchain.toml
[toolchain]
channel = "nightly-2026-07-11"
components = ["rust-src", "rustfmt", "clippy"]
.cargo/config.toml
[build]
target = "host-tuple"

rust-toolchain.toml pins the nightly for both. .cargo/config.toml puts both builds in target/<host>/debug.

Without the files, rawr run stops with RAWR-ENVIRONMENT-PROJECT-BUILD and prints the files to add. A crate with no dependencies doesn’t need them.

A member of a Cargo workspace doesn’t need them either. cargo build takes its toolchain from the workspace’s root, and rawr doesn’t ask the whole workspace to use the nightly. rawr builds the member with the nightly in the workspace’s target/. cargo build then compiles the member’s dependencies a second time, with the workspace’s toolchain.

rawr keeps what it makes for a crate in target/rawr. For a workspace member, that is target/rawr/members/<path> in the workspace’s target/, where <path> is the member’s directory. cargo clean removes it.

Use a dependency

Declare the dependency in Cargo.toml and import its items with use. You write no bindings.

Cargo.toml
[dependencies]
mathx = { path = "mathx" }
mathx/src/lib.rsa native crate
pub fn double(x: i64) -> i64 {
    x * 2
}
src/main.rsneeds the mathx crate
// rawr
use mathx::double;

fn main() {
    for n in 1..=3 {
        println!("{n} doubled is {}", double(n));
    }
}
on your machinerawr run1 doubled is 2 2 doubled is 4 3 doubled is 6

The first run compiles the dependencies and the runner. That took about 80 s for this crate on an Apple Silicon Mac. After an edit to src/main.rs, the next run reused that build and took about 2.4 s.

rawr uses the dependencies as Cargo resolves them. It reads only the items your code uses.

Native modules

A module of your crate whose first line isn’t // rawr is native Rust. rawr-import compiles it with Cargo, and marked code calls it as it calls a dependency. Calls from native code into marked code need a native crate root, as Run explains.

Imported values

A struct in a marked file can hold a value of an imported type. It can derive Default, Debug, Clone and Copy when the crate implements that trait for the type. == and != work when the crate implements PartialEq. An imported value can key a HashMap or a HashSet when the crate implements Hash and Eq. {:?} prints the crate’s Debug text. to_string() and {} print its Display text. Preset::to_string is a function value, as in pick_list(.., Preset::to_string).

A method whose result rawr cannot hold returns that result’s Display text instead, when its type has one. So chrono’s now.format("%H:%M:%S") is a String.

A method can return a borrow guard, which is a type that borrows the value it came from and dereferences to what it guards. RefCell::borrow_mut returns one, and so do Freya’s State::read and State::write. *count.read() is the guarded value, and *count.write() += 1 changes it, as in Rust. rawr never keeps a guard. Each read calls the method, copies the value with its Clone, and drops the guard before the call returns. Each store calls the method again and assigns through the guard. So *count.write() += 1 calls write twice where Rust calls it once, and a let mut value = count.write(); calls it at each use of value. A guard that is only Deref, or whose method takes arguments, gives a copy of the value as a &T.

An imported type written without its defaulted type arguments takes their defaults. So palette’s Hsl is Hsl<Srgb, f32>. A default that rawr cannot name, such as iced’s renderer, still has to be written. iced’s own text_editor::Content needs none, since rawr-iced declares it.

A Rust function or method that returns a Vec, a slice or a tuple gives a rawr Vec or tuple. An immutable static of a slice or a number reads as its value, as preset::ALL does for pub static ALL: &[Preset] = &[..]. A generic Rust function or method can take a tuple of Rust types, as Freya’s background((35, 35, 35)) does. Rust functions still cannot take a Vec or a slice from rawr.

An associated constant of an imported type reads as a new value each time, as Color::WHITE does in Rust. An imported enum’s own functions are called beside its variants, so torin’s Size::fill() and Size::Fill are both there.

A match or if let can match a variant of an imported enum, as in echo::Event::Connected(connection) => ... The pattern takes the variant’s fields as clones.

An imported value is dropped with its last owner in your code, as in Rust. A tokio channel closes once its last sender is gone.

A trait’s default method is a method of each type the trait is implemented for, as Rust has it. Freya’s rect().expanded().center().child("Hello") calls three, through a blanket impl, an empty one and a generic method. Each returns the Rect it took as self.

One item rawr can’t hold doesn’t stop a use krate::*. rawr leaves that item out, and a call to it says why.

A function or method can return impl Trait of a dependency’s trait, as in Freya’s fn app() -> impl IntoElement. As in rustc, the type it stands for is the type the body returns. It may sit inside an Option, a Result, a Vec, a Box, a tuple or a reference. rawr doesn’t check that the body’s type implements the trait. cargo check reports it. A caller sees the body’s type, so it can call more than the trait’s methods. cargo check reports that as well.

Generic items and your own types

A generic Rust function or method can take your own types, as mpsc::channel::<Job>() does with a struct from a marked file. rawr builds the item once in its runner at rawr::Value, which carries any of your values as they are. A value that comes back, as recv gives a Job, is checked against the type you named.

rawr::Value is Send, Sync, Clone and Debug. Its Clone and Debug are your type’s own, derived or written by hand. A T: Clone or T: Debug bound is checked on your type, as rustc checks it, so a struct without Clone can’t fill a T: Clone. A bound rawr::Value can’t meet, such as Default, Copy, Hash or Deserialize, stops the build with an error that names the bound. Call such an item with a Rust type.

A range of floats, as in 0.5..1.0, is a value that a generic item can take. rand’s rng.random_range(0.5..1.0) is one. Its R: SampleRange<T> bound has an impl for Range<T>, so T is the range’s own float, as rustc infers it. rawr reads that from the crate’s implementations of the bound’s trait.

To native code, all of your types are one type. A native cast by TypeId, such as Box<dyn Any>::downcast, succeeds between any two of them. rawr checks the value that comes back against the type you named, so a cast to another of your types stops the program with an error where Rust gives None. A value native code hands to your closure is checked against the closure’s parameter in the same way.

A parameter F: FnOnce() -> R takes a closure of yours, as spawn_blocking does. So do F: Fn(..) -> R + 'static and F: FnMut(..) -> R + 'static. Native code may call those again. The closure runs with an evaluation of its own on whichever thread calls it.

A closure can take and give values of imported types when native code calls it on the thread that runs your program. That is the case when a native call of yours calls it back before it returns, as Freya’s launch calls your app on each frame. On another thread, such a closure stops the program with an error.

A parameter impl Into<T> takes a closure, or a function of yours, when T has one From<F> implementation for a callable F. Freya’s WindowConfig::new(app) takes fn app() through impl From<F> for AppComponent, where F: Fn() -> E. Its on_press(|_| ..) takes a closure through impl From<H> for EventHandler<D>, where H: FnMut(D). Freya calls it on each press.

Any other parameter impl Trait is a type parameter that the argument fills, as <T: Trait> is. Freya’s width(impl Into<Size>) takes Size::fill(), and its color(impl Into<Fill>) takes Color::WHITE. For impl Into<T>, rawr reads T’s From implementations. When the argument fits exactly one of them, its number literals take that implementation’s types, as rustc infers them. So background((35, 35, 35)) passes (u8, u8, u8), because Fill converts from no other tuple of three, and padding(12.) passes an f32. Whether the bound holds is rustc’s to check where the runner calls the method.

An async method that borrows its receiver crosses too. Run explains how its future holds the receiver.

Known gaps

  • A program that rawr-import runs exits with status 1 when it fails, a panic included. Rust would exit with 101.
  • rawr-import restarts a program with a marked main when you save. A native main picks up a body edit at its next call. Reload says more.
  • A guarded value without Clone stops the program where it is read. A guard of a Vec or a tuple can be read but not changed yet. A guard inside an Option or a Result, as Mutex::lock gives, isn’t supported yet.
  • A method that is generic over a sealed trait, such as itoa::Buffer::format, can’t be called yet.
