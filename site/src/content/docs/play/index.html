Playground

The playground runs Rust in your browser. A program shows its output.

The editor

Ctrl+Enter or Cmd+Enter runs the code.

The Examples menu lists plain Rust programs. Its Rustlings group holds solutions from rustlings, used under its MIT licence. Each one names the file it came from. A first visit opens the first example. The editor keeps your latest snippet, so /play opens where you left off.

The playground has the same limits as the bot.

Every snippet runs in your browser. No server runs it. rawr loads into the page once the page is up, so it doesn’t hold up the first paint. A program shows its output as the bot would. An edit runs the program again after a short pause.

A snippet that uses one of the playground’s crates, such as iced, runs on the playground’s prebuilt runner, built for the browser. Its window is drawn in the output pane and answers clicks and keys there. What it prints shows under the window. An edit reloads the program in place, as rawr run reloads a save, so it keeps its state: a counter keeps its count. An edit that doesn’t compile shows its error under the window, and the program keeps running its last good code. An edit that can’t reload in place, such as one to main or to the fields of a type a live value holds, starts the program over in a fresh window, and the status line says why. A change to what only view builds shows at the program’s next message, such as its next click, as in rawr run. Run always starts the program over.

A run that can’t start in the browser shows why in the output pane and stops. That happens when rawr or the prebuilt runner doesn’t load in the page. It also happens when rawr itself stops on a program, and then the next run loads a fresh copy of rawr.

A frontmatter block

A snippet may start with a cargo-script frontmatter block that declares its dependencies. The playground builds nothing. It runs such a snippet when each dependency it names is one of the prebuilt runner’s crates, at a version the runner’s manifest allows. Any other dependency gets one line that names the crates the browser has. The ?play bot on Discord builds its approved crates.

The address

The page’s address keeps the example you picked. An example you load adds its name after a #, such as /play#word-count. Editing the code drops that name, because the code is no longer the example’s. Opening an address restores the example. Picking an example replaces the address and doesn’t add to the browser’s history.

Share links

Share saves the code and gives a link of the form /play/<id>. The link never has an example’s name, because its code is the share’s. A share’s code also wins over an example’s name in an address. A shared link shows a preview card in Discord and other apps. The card shows the first line of the program’s output. A share that nobody opens for 90 days is deleted.

What runs

A plain program runs the way rawr run runs a file. The reply is its stdout and stderr in the order it wrote them.

A snippet of statements alone runs as the body of main. If its last expression has no semicolon, its value is printed with {:?}. Its locals drop at its end, as main’s do. A snippet that opens with an inner attribute, such as #![allow(dead_code)], is a file and runs as written.

let xs = vec![3, 1, 2];
xs.iter().sum::<i64>()

The reply shows the exit status when it isn’t 0.

A snippet that uses iced, or whose main is async, gets its message instead of a run.

On the home page, the iced counter runs in the browser with iced itself, on the playground’s prebuilt runner built for the browser. Its window is drawn in the page, in place of its output, and its buttons answer clicks there. Before Run, its output is a picture of its first frame. The prebuilt runner in the browser says how it runs.

What a snippet can reach

A snippet runs in a sandbox. It has no files, no environment variables and no network. It can use rawr’s std and the prebuilt runner’s crates. The Play reference lists every limit and every difference from rawr run.
