Debugging

You can pause a rawr program at a breakpoint and step through it. While it’s paused, you can read its values and evaluate Rust in any call on its stack. A save still reloads the program while you debug it.

Each rawr run hosts one debugger session. A shell attaches to that session and shows it to you:

  • rawr gui opens a window.
  • rawr tui runs in a terminal.
  • rawr dap serves editors over the Debug Adapter Protocol.
  • rawr mcp serves coding agents.

Several shells can attach to the same run. The playground has a separate debugger that runs in the browser.

The debugger window

rawr gui [path] opens a debugger window on the program at path. It attaches to a rawr run of the program if one is going, and starts one if not. Closing the window ends a run it started.

The window runs in its own process, so it keeps drawing while the program is paused.

The install script doesn’t include the window yet. rawr gui runs a rawr-gui binary from the directory rawr is in. Build it from source with:

cargo install --locked --git https://github.com/airstrike/rawr rawr-gui

Figure 1 shows the window paused at a breakpoint.

  1. The toolbar continues or pauses the program on F8. It steps over on F10, into on F11 and out on Shift+F11. To the right of the buttons is the program’s state, such as paused (breakpoint) at line 18.
  2. The source shows the file the program is paused in and highlights the paused line. Before the first pause it shows src/main.rs, or the file you ran. Click left of a line number to set a breakpoint, and click its red dot to clear it. The window can’t open a file on its own. To set a breakpoint in a file the program isn’t paused in, use another shell.
  3. The call stack lists the calls the program is in, with the innermost at the top. Each row has the function’s Rust path and its file and line. Click a row to show that call’s bindings and to evaluate code in it.
  4. The bindings are the selected call’s. A value with fields or items opens to one row for each. In Figure 1, the map players is open to one row per key.
  5. The console evaluates Rust in the selected call while the program is paused. Type code and press Enter.
  6. The output is what the program printed.

On macOS, a program that opens a window also gets a Frame pane above the call stack. The pane shows the program’s window as of its last capture. The debugger captures it when the program starts or continues, and when you click the toolbar’s Refresh frame button.

In a terminal

rawr tui [path] is the same debugger in a terminal. Like the window, it attaches to a run or starts one.

The source is on the left. The frames, the bindings and the breakpoints are on the right. The program’s output and your evaluations are below them. The keys are listed along the bottom. Tab moves between the source, the frames and the bindings. The arrow keys or j and k move within one.

KeyDoes
bSets or clears a breakpoint on the source line under the cursor.
BAsks where to break. Type file:line, a line number in the file shown, or a function’s name.
pPauses the running program.
s, i, oSteps over, into and out.
cContinues.
eAsks for Rust to evaluate in the selected frame.
Enter, →, ←Open and close a binding in the bindings pane.
qQuits. A run that rawr tui started ends with it. A run started elsewhere keeps going.

In your editor

rawr dap is a Debug Adapter Protocol server on stdio. It ships with rawr. An editor that speaks the protocol can launch a program under it or attach to one that’s already running.

  • Launch runs rawr run on program with args. program is a crate’s directory, its Cargo.toml or one .rs file. Relative paths start at cwd. The program waits at its first statement until the editor has sent its breakpoints and configurationDone, so a breakpoint in startup code is hit. If a rawr run of the program is already going, launch attaches to it and says so in the Debug Console.
  • Attach connects to a rawr run of program that’s already going. With no such run, attach fails with an error.
  • Disconnecting ends a run the editor launched. A run started elsewhere keeps going.
  • The call stack names each frame by its Rust path, such as counter::App::update.
  • The Debug Console shows what the program prints. It also says when a save reloads or restarts the program. A save that fails the check shows its errors there.
  • The Debug Console, watch expressions and hovers evaluate code as Values and evaluation describes.
  • A value in the Variables pane, or a watch expression, can be given a new value. It is assigned with eval in that value’s frame, so Rust decides whether the write is allowed. Writing to an immutable binding, or to a field behind &self, fails with rustc’s error.
  • Launch refuses a program that draws a terminal UI, such as one that uses ratatui or crossterm. Run it with rawr run in a terminal and attach to it.

VS Code

The Rawr extension adds a debugger of type rawr. It isn’t on the Marketplace yet. From a clone of rawr’s repository, package it and install it:

cd editors/vscode-rawr
npx @vscode/vsce package --skip-license --out rawr.vsix
code --install-extension rawr.vsix

Without a launch.json, press F5 in a marked .rs file. The extension looks for the nearest Cargo.toml above the file and runs that crate. With no Cargo.toml above it, the file runs on its own. F5 in an unmarked .rs file shows an error and runs nothing.

To keep a configuration, add it to .vscode/launch.json. The Rawr: run snippet writes this one:

{
  "type": "rawr",
  "request": "launch",
  "name": "Rawr: run",
  "program": "${workspaceFolder}"
}

The Rawr: attach snippet writes the same with "request": "attach". Set rawr.path if rawr isn’t on your PATH.

Neovim

With nvim-dap:

local dap = require("dap")
dap.adapters.rawr = { type = "executable", command = "rawr", args = { "dap" } }
dap.configurations.rust = dap.configurations.rust or {}
table.insert(dap.configurations.rust,
  { type = "rawr", request = "launch", name = "rawr run", program = "${workspaceFolder}" })
table.insert(dap.configurations.rust,
  { type = "rawr", request = "attach", name = "rawr attach", program = "${workspaceFolder}" })

Helix

Add this to the project’s .helix/languages.toml. It replaces Helix’s Rust debugger in that project only.

[[language]]
name = "rust"

[language.debugger]
name = "rawr"
transport = "stdio"
command = "rawr"
args = ["dap"]

[[language.debugger.templates]]
name = "rawr run"
request = "launch"
completion = [{ name = "program", completion = "filename", default = "." }]
args = { program = "{0}" }

[[language.debugger.templates]]
name = "rawr attach"
request = "attach"
completion = [{ name = "program", completion = "filename", default = "." }]
args = { program = "{0}" }

Then run :debug-start rawr run, or press Space g for the debug menu.

Zed

Zed gets debug adapters from extensions. rawr has no Zed extension yet. One would declare [debug_adapters.rawr] in its extension.toml. Its get_dap_binary would return the command rawr with the argument dap. The adapter talks over stdio. With such an extension installed, .zed/debug.json names the adapter:

[
  { "label": "rawr run", "adapter": "rawr", "request": "launch", "program": "$ZED_WORKTREE_ROOT" },
  { "label": "rawr attach", "adapter": "rawr", "request": "attach", "program": "$ZED_WORKTREE_ROOT" }
]

In the playground

The playground’s debugger runs in the browser. Click the bug icon next to Share to turn it on. The first time, the page downloads a debugger build of its WebAssembly module. Then the program runs again from the start under the debugger. A debugger panel opens to the right of the output. A console opens under the code. Click the bug icon again to turn the debugger off.

The debugger needs WebAssembly JS Promise Integration (JSPI) to pause a program. In a browser without JSPI, the bug icon is greyed out. Clicking it says why.

  • Click a line number to set a breakpoint, and click it again to clear it. Breakpoints you set before a run are in place before main starts.
  • The panel’s toolbar takes the same keys as the window: F8, F10, F11 and Shift+F11.
  • The panel shows the call stack and the bindings of the call you select.
  • Click a value without fields or items in the bindings to change it. Type Rust and press Enter to assign it in the selected call. If Rust refuses the assignment, rustc’s error shows under the value. Escape cancels.
  • The console evaluates Rust in the selected call. Enter evaluates, and Shift+Enter adds a line.
  • A breakpoint pauses main and the functions it calls. It also pauses inside an event listener or an animation-frame callback, such as ratzilla’s key handler. Any other call from the page into the program runs to its end without pausing.

Breakpoints and steps

  • A breakpoint goes on a line or on a function. A function breakpoint pauses at the function’s first statement.
  • A line with no statement on it is refused, and the shell says why.
  • A breakpoint stays across saves while its line’s text is still in the file. If the line moves, the breakpoint moves to the nearest line with the same text. If no line has that text, the breakpoint is removed.
  • A step stops at the next statement the program wrote. It stops at most once on a line.
  • Pause stops a running program at the next statement it runs. A program waiting in a window’s event loop pauses when the loop next calls into it.
  • A step past the end of a function that the event loop called goes back into the loop. It stops at the next statement the program runs, such as one in the next view or update.

Values and evaluation

Each binding shows as Rust’s {:?} prints it. Your own types print through their Debug impls and derives. A crate’s type prints through that crate’s Debug impl. A type without one says so, as rustc does. A value with fields or items opens to a row for each. Those rows open too.

Evaluated code runs where the program is paused. rawr compiles it as a block written just before the paused statement, so the bindings in scope there are in scope for it. rustc’s rules for that line apply. Changing a binding that isn’t mut fails with rustc’s error. So does a borrow that conflicts with one the program still holds.

The answer is the value of the code’s last expression. An assignment such as self.value = 100 answers (), with or without its ;. rawr reads it through a borrow, so evaluating a binding doesn’t move it. A change the code makes stays, and the program goes on with it. Bindings the code declares end with it.

With a caller’s frame selected, the code runs in that caller, just before the statement that made the call. A change it makes stays in that caller. A binding the running call borrows, such as one passed to it as &mut, is refused until the call returns. rawr mcp’s eval follows the same rules.

Attaching to a running program

A shell finds a run by the program’s path. It attaches to a rawr run of that program wherever the run was started. If none is going, rawr gui, rawr tui and an editor’s launch start one. A run that a shell started has the debugger from its start.

Two rawr runs of one program each host their own session. A shell attaches to the newest and names the others by pid. rawr tui --pid <pid> and rawr gui --pid <pid> attach to a run you pick. An editor’s attach does the same with "processId". For a run that a shell started, the pid is the shell’s.

A run you start in a terminal doesn’t load the debugger until a shell asks for something that needs it, such as a breakpoint or a pause. Until then, the debugger costs the program one flag check at each step. Attaching alone doesn’t load it, and neither do screenshots or window input.

When a shell asks, the program loads the debugger at its next step. It keeps its process and its state. From then on it also records its calls for the call stack. A program that restarts after a save has the debugger from its start.

A debugger that arrives while the program runs doesn’t see the calls already under way. When the program pauses, the call stack lists only the calls made after the debugger arrived. If the program pauses in a call that was already under way, the stack shows that one call alone. You can’t read bindings or evaluate code in the calls the stack leaves out. Stepping out of a call that was already under way still stops at its caller’s next statement.

The run keeps the last 256 KiB of the program’s output. A shell that attaches shows that first, then each new piece as the program prints it. In a program with Rust dependencies, this covers what the program’s own code prints. Text that a crate writes straight to the terminal stays in the terminal. A run that a shell starts sends the shell all of its output, a crate’s writes included. An editor that attaches to a run started in a terminal says in its Debug Console which output it hears.

Several shells on one run

Any number of shells can attach to one run. They all see the same pauses and reloads. If an agent’s click through rawr mcp reaches a breakpoint, your editor stops there too. A continue from the editor lets the agent’s program go on.

Breakpoints belong to the run. A breakpoint set or cleared in one shell shows in the others right away. An editor adds or removes it in its gutter. A shell that attaches later shows the breakpoints already set.

Limits

  • The debugger sees only marked files. Code in Rust dependencies and in unmarked modules runs natively. A step can’t stop inside it, and its lines take no breakpoints.
  • A pause inside a call from native code, such as a window’s event loop, holds that loop. The window doesn’t redraw or take input until the program goes on.
  • The program pauses one thread at a time, and its other threads keep running. A thread that reaches a breakpoint during a pause waits for that pause to end, then pauses. An editor shows them all as one thread.
  • Breakpoints take no conditions, hit counts or log messages.
  • A panic doesn’t pause the program. It ends the program as it does without a debugger.
  • rawr gui and rawr tui start a program right away. To stop in code that runs at startup, launch the program from an editor, which waits for its breakpoints.
  • A value whose Debug text isn’t in a shape the standard derives write shows whole, without fields. A hand-written Debug impl may print such text.
  • The debugger runs on Unix systems. On Windows, rawr run has no debugger.
