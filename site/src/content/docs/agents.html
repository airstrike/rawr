Agents

Connect a coding agent such as Claude Code or Codex to rawr. The agent makes a Rust crate, checks it, runs it and sees each save reload.

rawr mcp is a Model Context Protocol server on stdio. It comes with rawr itself. Installed extensions add tools to it. The agent edits files with its own tools, and rawr does the rest.

Install

Install rawr:

cargo install --locked --git https://github.com/airstrike/rawr rawr-cli

That is enough for programs with no dependencies. A program with Rust dependencies needs rawr-import. An iced app needs rawr-iced. Imports and iced say how to install them. The server names whatever is missing when it starts, with the commands that install it.

Register the server

Run rawr init in the project the agent works in:

rawr init

It looks for a .claude or .codex directory to tell which agent the project uses. Pass --claude, --codex or both to choose.

  • For Claude Code it writes .mcp.json.
  • For Codex it writes .codex/config.toml, with a 120 s tool timeout and a 30 s startup timeout.

The entry runs rawr by its absolute path, with args = ["mcp"] and the project as its working directory. A rawr elsewhere on PATH is never started. Running rawr init again replaces the entry. The old file is kept beside it as .mcp.json.bak or config.toml.bak. Every other setting in the file stays.

Restart the agent once to load the server. An extension installed later adds its tools without another rawr init.

The loop

  1. new makes a crate whose src/main.rs starts with // rawr.
  2. The agent edits the files with its own tools.
  3. check returns each error with its file, line and column.
  4. run runs a command-line program to its end, with arguments and stdin.
  5. start runs a window or a long-running program and keeps it running.
  6. After each save, wait says whether the program swapped, restarted or failed.
  7. screenshot shows its window, and stop ends it.

The tools

Every tool takes a path: a crate directory or a .rs file. A relative path starts at the project the server runs in. Each result has data in structuredContent and a text form an agent can act on.

ToolWhat it does
newMakes a crate at path. template picks a template an installed extension offers, such as iced. A path inside a Cargo workspace that doesn’t list it is refused, with the fix.
checkRuns rawr’s check and cargo check. Each diagnostic has an absolute file, line, column, end_line, end_column, code, severity, message and help. One from rustc may carry a suggestion. The text form has one file:line:col: error[CODE]: message line per diagnostic.
runRuns the program with args and stdin until it ends or timeout_ms passes. It returns the exit status, stdout and stderr.
startStarts the program and keeps it running. It answers running, failed with diagnostics, or building while a first start builds. Starting the same project again replaces the program.
waitWaits for the next events of the started program and returns them with the output since the last call.
statusSays what each started program is doing, without waiting.
stopStops the started program.
screenshotReturns a PNG of the started program’s window alone.

The events wait returns are these:

  • running: the program runs.
  • swapped: a save changed the running program in place, and it kept its state.
  • restarting: a save restarts the program, for the reason given.
  • failed: a start or a save failed, with diagnostics. The last good program keeps running.
  • ended: the program ended, with its status. The next save runs it again.

Each event has a number. wait goes on from the last event it returned, so an event that came between two calls is still returned. Pass cursor to start from another one.

rawr-iced adds tools for iced apps:

ToolWhat it does
list_previewsLists the project’s #[preview]s without rendering them.
render_previewRenders one preview and returns the PNG.
click, type_text, press_keySend input to the running window. A click finds a widget by its text or id, or goes to a point.
doSends a list of clicks, text and keys in order.
resetBoots the app afresh.

Each input tool can return a screenshot. An iced window takes its own screenshot, so it needs no permission. Previews has more on previews.

An example session

An agent making a command-line tool calls these, in order:

new    {"path": "hello"}
check  {"path": "hello"}
run    {"path": "hello", "args": ["-n", "pie"], "stdin": "apple\ncherry\n"}

An agent making an iced app calls these:

new         {"path": "counter", "template": "iced"}
start       {"path": "counter"}
wait        {"path": "counter"}
do          {"path": "counter", "actions": [{"action": "click", "text": "Increment"}], "screenshot": true}
wait        {"path": "counter"}
stop        {"path": "counter"}

The first start of an app with dependencies builds them, which can take minutes. It answers building within the call’s time limit, and wait follows the build until the app runs.

The programs the server starts

The server owns the programs it starts. It runs one program per project, as rawr run would at a terminal. The program’s stdin is what stdin gave, then the end of input. Its output is kept for wait.

  • stop ends the program and everything it started.
  • A second start of the same project ends the first program.
  • When the agent closes the server, its programs end.
  • When the server is killed, its programs notice and end themselves.

A window started outside the server, with rawr run in a terminal, still works with rawr-iced’s window tools. stop leaves it alone.

Limits

  • No call takes longer than about 45 s. A longer build answers building, or check says it is still checking. Call it again to keep waiting.
  • start refuses a program that draws a terminal UI, such as a ratatui app. Run it with rawr run in a terminal of your own.
  • A screenshot of a window that isn’t iced’s uses macOS’s window capture. macOS asks for Screen Recording permission for the app the agent runs in. Other systems have no such capture yet.
  • One project has one started program at a time.
