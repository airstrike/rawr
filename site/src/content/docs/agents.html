Agents

Connect a coding agent such as Claude Code or Codex to rawr. The agent makes a Rust crate, checks it, runs it and sees each save reload.

rawr mcp is a Model Context Protocol server on stdio. It comes with rawr itself. Installed extensions add tools to it. The agent edits files with its own tools, and rawr does the rest.

Install

Install rawr:

cargo install --locked --git https://github.com/airstrike/rawr rawr-cli

That is enough for programs with no dependencies. A program with Rust dependencies needs rawr-import, and so does an iced app. Imports says how to install it. The server names whatever is missing when it starts, with the commands that install it.

Register the server

Run rawr init in the project the agent works in:

rawr init

It looks for a .claude or .codex directory to tell which agent the project uses. Pass --claude, --codex or both to choose.

  • For Claude Code it writes .mcp.json.
  • For Codex it writes .codex/config.toml, with a 120 s tool timeout and a 30 s startup timeout.

The entry runs rawr by its absolute path, with args = ["mcp"] and the project as its working directory. A rawr elsewhere on PATH is never started. Running rawr init again replaces the entry. The old file is kept beside it as .mcp.json.bak or config.toml.bak. Every other setting in the file stays.

Restart the agent once to load the server. An extension installed later adds its tools without another rawr init.

The loop

  1. new makes a crate whose src/main.rs starts with // rawr.
  2. The agent edits the files with its own tools.
  3. check returns each error with its file, line and column.
  4. run runs a command-line program to its end, with arguments and stdin.
  5. start runs a window or a long-running program and keeps it running.
  6. After each save, wait says whether the program swapped, restarted or failed.
  7. screenshot shows its window, and inspect reads its values.
  8. break pauses it at a line or a function. step and continue go on from there.
  9. stop ends it.

The tools

Every tool takes a path: a crate directory or a .rs file. A relative path starts at the project the server runs in. Each result has data in structuredContent and a text form an agent can act on.

ToolWhat it does
newMakes a crate at path. template picks a template an installed extension offers. No extension offers one today. A path inside a Cargo workspace that doesn’t list it is refused, with the fix.
checkRuns rawr’s check and cargo check. Each diagnostic has an absolute file, line, column, end_line, end_column, code, severity, message and help. One from rustc may carry a suggestion. The text form has one file:line:col: error[CODE]: message line per diagnostic.
runRuns the program with args and stdin until it ends or timeout_ms passes. It returns the exit status, stdout and stderr.
startStarts the program and keeps it running. It answers running, failed with diagnostics, or building while a first start builds. Starting the same project again replaces the program.
waitWaits for the next events of the started program and returns them with the output since the last call.
statusSays what each started program is doing, without waiting. A paused program says where it is paused.
stopStops the started program.
screenshotReturns a PNG of the started program’s window alone.
inspectReads the started program’s values while it runs. It returns the file, line and function the program is in, and each binding in scope there as Rust’s {:?} prints it. name asks for one binding and file for one source file. frame reads a caller’s bindings.
breakSets a breakpoint on a line of a file, or on a function. It returns where the program paused, if it pauses within timeout_ms.
stepRuns the paused program to its next statement. kind is over, into or out.
continueLets the paused program run on. It returns where it pauses next, if it pauses within timeout_ms.
clearRemoves every breakpoint, or those on a file, a line or a function.

The events wait returns are these:

  • running: the program runs.
  • queued: a save reached a program with a marked main in a native loop. The loop takes it at its next call into marked code, and swapped follows. In Freya that is the next event.
  • swapped: a save changed the running program in place, and it kept its state.
  • restarting: a save restarts the program, for the reason given.
  • failed: a start or a save failed, with diagnostics. The last good program keeps running.
  • ended: the program ended, with its status. The next save runs it again.
  • paused: the program paused at a breakpoint or after a step, with its file, line and function. wait and status then say paused.
  • resumed: a paused program went on.

Each event has a number. wait goes on from the last event it returned, so an event that came between two calls is still returned. Pass cursor to start from another one.

Reading values

inspect asks the running program for its values. The program answers at its next step in its own code. With name, it answers at the next step where that binding is in scope. With file, it answers at the next step in that file.

inspect  {"path": "counter", "name": "counter"}
/work/counter/src/main.rs:16 in `counter::main`
counter = Counter { count: 41, label: "ticks" }
  • A value of the program’s own type prints through its Debug impl or derive.
  • A value of a crate’s type prints through the crate’s Debug impl. A type without one says so, as rustc does: `Window` doesn’t implement `Debug`.
  • A program with Rust dependencies answers too. In an iced app, {"name": "state"} reads the state in update or view the next time iced calls one.
  • A program waiting for input or for an event runs none of its own code. inspect then says nothing was read within timeout_ms. Call it again once the program runs.
  • A &mut parameter and self read under those names.
  • The answer lists the calls the program is in. frame reads one of them: 0 is the function the program is in, 1 is its caller, and so on. A caller’s line is the line of its call.

Pausing and stepping

break pauses the running program when it reaches a line, or a function’s first statement. While it is paused, inspect reads the values where it stopped.

break    {"path": "counter", "file": "counter/src/main.rs", "line": 9}
inspect  {"path": "counter", "name": "count"}
inspect  {"path": "counter", "frame": 1}
step     {"path": "counter", "kind": "into"}
continue {"path": "counter"}
clear    {"path": "counter"}
  • step stops at the program’s next statement. over stays in the function, into goes into a function it calls and out returns from it.
  • Code in Rust dependencies runs whole. A step can’t stop inside a crate’s function.
  • A pause inside a call from native code, such as a window’s event loop, holds that call. The window doesn’t redraw or take input until the program goes on.
  • A breakpoint stays across saves while its line’s text is still in the file. When lines move, it moves to the nearest line with that text. When no line has that text, it is removed.

An example session

An agent making a command-line tool calls these, in order:

new    {"path": "hello"}
check  {"path": "hello"}
run    {"path": "hello", "args": ["-n", "pie"], "stdin": "apple\ncherry\n"}

An agent making an iced app calls these. Between new and start it adds iced to Cargo.toml and writes the app.

new         {"path": "counter"}
start       {"path": "counter"}
wait        {"path": "counter"}
screenshot  {"path": "counter"}
stop        {"path": "counter"}

The first start of an app with dependencies builds them, which can take minutes. It answers building within the call’s time limit, and wait follows the build until the app runs.

The programs the server starts

The server owns the programs it starts. It runs one program per project, as rawr run would at a terminal. The program’s stdin is what stdin gave, then the end of input. Its output is kept for wait.

  • stop ends the program and everything it started.
  • A second start of the same project ends the first program.
  • When the agent closes the server, its programs end.
  • When the server is killed, its programs notice and end themselves.

Limits

  • No call takes longer than about 45 s. A longer build answers building, or check says it is still checking. Call it again to keep waiting.
  • start refuses a program that draws a terminal UI, such as a ratatui app. Run it with rawr run in a terminal of your own.
  • A screenshot uses macOS’s window capture. macOS asks for Screen Recording permission for the app the agent runs in. Other systems have no such capture yet.
  • One project has one started program at a time.
